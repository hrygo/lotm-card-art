# LOTM 单卡制作 SOP

用于当前仓库中一张 `pathway:sequence` 卡的端到端推进。它是决策顺序和门槛，不替代仓库根 `AGENTS.md`、途径规则、`design/` 规范或用户的明确授权。

## 先判定本轮范围

先把用户请求归入一个或多个模式，再只执行已授权的阶段：

- `research`：证据、事实缺口和候选方向；不出正式图、不合成未批准声音。
- `design`：六维转译、主事件、构图、文字和误读边界；通过 design 门槛后才允许进入资产生产。
- `asset`：生成或排版真实图像/音频；逐项记录工具、输入、时间、参考和处理链。
- `review`：独立回读、视觉检查、文本/事实核对和批准记录。
- `release`：只有真实文件、尺寸、摘要、制作记录、当前审核和批准依据都齐全时才进入。

用户只要求审查或文案时，不顺手生成图、声音、安装包、issue、commit 或 push。用户明确要求“继续制作”时，也仍以当前单卡为边界。

## 1. 建立单卡上下文

1. 以当前工作区为仓库根，先读根 `AGENTS.md`、`pathways/AGENTS.md`、当前途径的 `AGENTS.md`；按阶段读取 `docs/workflow.md`、`design/semantic-contract.md`、`design/art-bible.md`、`design/layout-system.md`、`design/qa-rubric.md`。
2. 用 `catalog/pathways.json` 解析稳定的 `pathway_id`，用 `09`…`00` 解析序列；中文称谓只作检索种子，不能替代 ID 或中文底本证据。序列 `00` 是正式序列卡，不是特殊事件。
3. 检查 `git status --short`，保留用户已有改动；不要用上一张卡的批准、图片、摘要或角色身份替代当前卡。
4. 读取当前途径的 `direction.json`、`canon.json` 和 `sequences/<seq>/card.json`。需要任务快照时运行 `python3 tools/cardctl.py brief --card <pathway>:<seq> --draft`；普通 `brief` 只有在 design 门槛通过后才能使用。
5. 当前美术生产入口为 `docs/production-sop-v3.md`，五档视觉品质读取 `config/quality-color-tokens.json`，框徽接口按 `lotm-quality-frames` 执行；`docs/production-sop-v2.md` 与 `docs/production-sop.md` 仅作历史合同和迁移参考，不把旧四档、局部复刻或强制矢量要求重新作为当前艺术规则。角色内容读取 `docs/card-narrative-contract.md`。

同一角色可以有多张独立身份卡；序列可以有 0…N 张卡。`card_id`、`slot_id`、`character_id`、`identity_slice_id`、内容状态、叙事审核状态和个人收藏状态不可互相替代。

## 2. 研究与事实分层

- 先查 `sources/registry.json` 和当前 `canon.json`，再使用可访问的一手来源；在记录中标明来源、版本、范围和证据等级。
- 把每条内容标成原著断言、资料缺口、解释性概括或原创美术提案。`unresearched` 不得写成“不存在”；`documented_absence` / `not_applicable` 必须带范围和依据。
- 层级从 `config/sequence-hierarchy.json` 读取，不自行重写：9–8 低序列、7–5 中序列、4–3 半神/圣者、2–1 天使、非编号状态“天使之王”、0 真神。不要把“天使之王”当序列编号，也不要把序列 0 当事件卡。

### 全序列层级的视觉渐变

将“序列越低越像人，序列越高越像神；人性占比递减，神性与抽象度递增”作为 9→0 的连续设计轴，而不是只给序列 0 的特例规则。这里的“人性”指人类尺度、可辨的人物行为、社会/生活处境和具体代价在画面中的占比，不是道德评价；“神性”指权柄、规则、非人格作用和环境主导权的占比。

| 序列 | 默认视觉重心 | 执行要求 |
| --- | --- | --- |
| 9–8 | 人类尺度、人类行为、具体职业/处境为主 | 保持主体、动作和环境可直接辨认；超凡力量通过局部、即时且有因果的效果出现。 |
| 7–5 | 人性与非凡性并存 | 人物仍清晰，角色性格/扮演法仍可见；能力开始改变空间、关系或现实表面，但不能把人类锚点抹掉。 |
| 4–3 | 神性开始通过人的载体显现 | 人物可成为神性的载体、见证者或仪式节点；象征关系、仪式组织和环境压力的权重上升，肉身不再承担全部叙事。 |
| 2–1 | 权柄、规则和化身关系主导 | 人格和肉身退居次位，可使用碎片、化身、几何、概念空间或非人格作用；仍须保留准确身份锚点和可回读事实。 |
| 0 | 非人格真神权柄与法则主导 | 以权柄、象征、法则和神性关系为主体；人形只能作为残留锚点，不能继续作为默认主视觉中心。 |

每张卡在 design 记录中补齐三个回读问题：人类锚点是什么、神性压力如何介入、抽象度由什么具体载体承载。不要把梯度机械化为“低序列必须肖像”或“高序列必须无人形”；主事件、途径事实和限制可以调整具体形式。序列递进不得只靠加亮、加大、王冠、翅膀、触手或黑雾完成；抽象化也不得以空泛氛围替代六维事实。
- 研究结论写入 `docs/research/` 或当前卡的记录；不复制原著全文，不把二手页面当中文底本，不把角色持有物自动升级为该序列固有能力。

## 3. 六维语义与内容方案

为 `identity`、`acting`、`abilities`、`potion`、`ascension`、`limitations` 各写清：

`证据/缺口 → 语义意图 → 可见载体 → 精度（exact/summary/evocation）→ readback → misreading_guard`。

- 一张卡只有一个主视觉事件；一个事件可以承担多个维度，但必须逐项解释因果和可观察线索。
- 身份源保留准确序列名与数字。当前愚者卡面采用固定的愚者途径标识、顶部独立艺术数字、右侧序列名和底部姓名；历史“途径标识＋数字融合圣徽”继续保存为参考资产，但不自动塞入当前数字圆洞。卡面不添加导轨、百科说明或主体内文字；可见载体须与当前语义 cue 一致。扮演表达行为原则；能力表达可辨认的效果；魔药对应已核验关键要素；晋升表达进入当前序列的条件；限制表达具体边界或风险。
- 配方/仪式是“进入当前序列”的要求，扮演/能力是“成为当前序列”后的性质；不把下一序列能力提前放入当前卡。
- 精确名称、数量和逻辑条件使用可读文字、数字或已有项目图例；抽象氛围不能冒充完整配方或规则。
- `direction.json` 只是原创视觉提案。途径形状、材质和异常方式要能与相近途径区分；序列递进靠主事件和关系结构，不靠单纯加亮、王冠、翅膀或触手。
- 高序列可以用概念空间、仪式拓扑或非人格主体；序列 0 是这条渐变的终点，尤其优先表现权柄、象征和规则关系，不能默认以人形肖像为主。低序列则优先保留人的动作、处境和可识别环境；这是一条全序列的默认权重轴，不是替代证据的风格标签。

## 4. 文案、图像与音频生产

### 文案

完整单卡的内容清单包含 greeting（问候）、catchphrase（口头语）和 story（分章角色故事），不是仅有人名和图片。按仓库 card-narrative schema 与模板建立独立内容包，绑定 card/slot/character/identitySlice、时间段及剧透边界；缺少文案明确记 gap。口头语区分有证据的原著引文、基于证据的概括和原创拟写，不把单次台词未经核对称为惯常口头禅。故事由事件、行动、心理变化与代价组成，不写成能力清单，不借未来身份/能力填充。正文不进入主插画，只转译相关事件和情绪意向。

使用 `python3 tools/production.py check-content <内容包路径>` 检查并取得计算摘要；`--ready-for-audio` 只检查包内文字批准，不调用服务或赋予声音授权。内容摘要包含身份、时间/剧透边界、来源与证据；修改任一项后重新审核。生产内容包与 App 数据类型语义对齐，但不是现成导入器，不宣称已完成应用接入。

先完成逐字文案和来源标记，再请求用户审核。用户未明确批准时保持 `draft`，不让任何 TTS 入口播放。批准必须绑定内容摘要：`NarrativeReview.approved(contentDigest:) == contentDigest`；内容变化会使旧批准失效。

### 图像

通过 design 检查后，使用实际可用的图像工具和附件生成一张完整正面：2:3、正视、一图一牌、边框完整。当前 Agentic 工作画布沿用工具实际原生尺寸（愚者样板通常为 `1024×1536`）；标准 `2048×3072` 与收藏 `4096×6144` 只在完整原生卡通过视觉验收后，从同一原生整幅各做一次最终采样。愚者当前由 `production/cards/fool-final-sampling-v1.json` 管理批准队列，使用 `python3 tools/production.py finalize ...` 执行，并用 `check-final-sample` 复核；清单仍为 pending 时必须拒绝。记录真实原始像素、最终像素、后处理链和 SHA-256，不把插值结果称为原生分辨率。

能保留时分离 `art`、`frame`、`emblem`、`type` 层；一体出图后逐字核对。图像模型不可用时交付任务单，不声称已成图。对于愚者当前视觉主路径，图像模型生成的完整原生卡本身就是视觉候选；确定性工具只做登记、原生测量、摘要和门禁，不以程序复刻替代 Agentic 图像。

当前愚者工艺以五档 Agentic 完整边框和十张 Agentic 完整序列框为视觉参考；主体、背景、边框、数字、序列名与姓名优先由 Agentic 在同一原生整幅中保持连续关系，不把无铭文底框裁出后再贴回，也不在 2K 成品上补字。品质色重点作用于框纹理、承接件及宝石，联合受光、分区明暗、受控色相流动；宝石保留亮点、折射和体色，不整卡套色。五档共骨架，色彩可流动而几何不可漂移；逐张核对途径标识、独立数字、序列名和姓名的正向可读性、保护域、笔画双轴居中及中央主事件。

### SpeechRail 音频

仅在当前请求授权声音制作时，对用户已批准的逐字文案生成声音；文字批准不自动授权 TTS、声音克隆或新音色注册：

1. 若已有批准的本地音频，优先复用并校验，不重复合成；只有在缺失或明确要求重制时才访问服务。
2. 访问服务前检查本机 loopback `/health`、`/readyz` 和 `/v1/voices`，选择实际 `available=true` 的音色；自定义 voice design 是持久化外部变更，除非用户另行明确要求，不默认注册。
3. API key 优先由 macOS Keychain 提供。若用户明确授权从已知 SpeechRail 运行时 `.env` 做一次性生成或 Keychain 配置，只提取所需字段，不 `source` 整个文件，不输出、不提交、不放入 app bundle。
4. 调用 `/v1/audio/speech` 时记录模型、音色、参数和响应格式；不记录 token、Authorization header、完整私密路径或未经批准的全文。
5. 校验每个音频是真实可解码文件，并记录时长、采样格式、SHA-256。应用资源名与 `NarrativeLine.audioResourceName` 一一对应；播放协调器必须在本地资源缺失时才回退网络合成。
6. 服务不可用或生成失败时停止当前音频交付，报告实际缺口，不绕过批准门槛、不伪造成功。一次性故障、临时绕行和历史 issue 留在制作记录或服务 issue 中，不写入本 SOP。

## 5. macOS 画册接入（仅当请求包含 App）

- 在 `NarrativeLine` 保存可选的本地音频资源名；批准门槛必须同时作用于唤醒、故事播放和公开 `speak` 入口。
- 更新 `DemoContent` 时保留卡牌视觉状态与叙事审核状态的独立性；一张视觉候选卡可以拥有已批准试听文案，但不能因此自动变成正式收藏。
- 在 `Resources/CardArt` / `Resources/Audio` 放入实际资产，并让 `scripts/build-app.sh` 显式复制资源；不要把密钥写入 `Info.plist`、Swift 源码、`UserDefaults` 或应用包。
- 先补领域/视图模型测试，再改播放或布局；构建后检查 `.app/Contents/Resources` 中的文件、格式和摘要，并做一次真实 UI 验收。

## 6. 审核、交付与停止条件

按阶段运行最小充分检查：

~~~bash
python3 tools/cardctl.py check --level scaffold
python3 -m unittest discover -s tests -v
python3 tools/cardctl.py check --level design --card <pathway>:<seq>
python3 tools/cardctl.py check --level release --card <pathway>:<seq>
git diff --check
~~~

`release` 只有在真实图像、选定尺寸、制作链、当前审核摘要和真实批准依据齐全时才应通过；机器检查不等于事实正确、视觉可读或人工批准。实际审图先隐藏方案做 360px 缩略图、768px 主事件和 100% 细节回读，再对照六维证据、相邻序列和相近途径。

交付时报告：当前卡与阶段、修改文件、真实资产及摘要、音频/图像参数、已执行命令和结果、尚未解决的证据/视觉/硬件限制。失败、缺口、未运行的人工检查要明确写出；没有用户明确要求，不 commit、push、发布或批量推进其他卡。

需要可复制的文件映射、命令和交付清单时，读取 [references/operational-checklist.md](references/operational-checklist.md)。
