# Agentic途径—序列融合

## 三段创作，一段工程

1. 母标识确定途径独特主意象、轮廓、负空间和设计Token（材质、配色、雕刻语法、光线）。母标识可复用，不代表各低序列已经具备途径全部能力。
2. 在相同Token下逐个生成准确可读的0–9，形成专属数字族；数字本身是艺术物料，不是普通字体。
3. 实际附上母标识和当前数字原图，由Agent选择共用笔画、嵌入浮雕、负空间或结构变形方案，重新生成单一完整徽章。数字是可读骨架，途径意象是组成骨架的材料和形体。必要时可加一枚已认可融合稿作风格参考，但不能把其数字误带入新稿。
4. 工程阶段才处理净底、边缘、缩放、定位、分层和卡面装配。不得把alpha失败等同于造型失败；不得声称棋盘格是真透明。

## 每项精确输入

保留现有kind=foundation任务合同，不给旧schema偷偷加字段。另存brief描述：pathway_id、digit、design_tokens、母标识/数字reference路径与sha256、fusion_strategy、invariants、art_reference、engineering_target、preserve_records。task.references与实际工具附件一一对应；spec.use_scope包含fusion:<pathway>和digit:<n>。
输入齐备后compile，完整读取prompt.txt，再逐个调用内置imagegen。输出是独立PNG，不用一张十宫格替代十个源文件。

## 愚者的已认可实例

设计Token：旧金、雾银、烟紫帷幕珐琅、象牙面具、微雕与镂空，左上柔光。数字骨架不牺牲识别。
0：两侧面具/帷幕围合可读椭圆；4：面具成为竖笔，帷幕形成斜笔和横笔；7：帷幕横梁接面具斜笔；9：帷幕环与面具共构上部，衣褶形成下垂尾笔。
用户明确要求保留artifacts/production/fool-fusion-{0,4,7,9}/v001及v002。这些是本项目实例，不把面具/紫金强加给其他途径。

## 分离状态与保留

- art_review：用户认可须记原话依据、指定版本/哈希和认可范围；可记录“方法与造型认可”，不得扩大成正式release批准。
- engineering：检查实际RGBA、镂空、边缘残底、小尺寸可读性；结果与艺术状态独立。
- preservation：保留选中原稿及用户要求保留的所有run，复核哈希。净底或风格返修新建run，不覆盖原图。未通过工程门槛的图仍可作为艺术参考，但不可冒充透明叠层。
- continuation：续补其余数字时沿用Token和双参考再创作，不必重做已认可数字。新稿逐一观察和登记，不自动获批。

尝试次数遵循当前task.limits；技术返修达到上限时记录问题并保留成果，不循环烧图。本次任务若只补齐造型，不顺带扩大到全22途径或重新净底旧稿。
