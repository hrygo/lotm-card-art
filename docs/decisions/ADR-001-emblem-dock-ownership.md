# ADR-001：母版固定 EmblemDock，圣徽本体独立装配

## Status

Accepted

## Date

2026-09-14

## Scope

本决定适用于后续新建或重制的途径母版框架、品质框架和圣徽装配。它不回写已经批准的历史图像，也不把旧的漂移稿、旧四档框或现有愚者序列9成品改名为新结构。

## Context

圣徽同时承担途径识别和序列识别，是卡牌最核心的身份组件。它还必须与边框形成真实的嵌入关系，并满足以下约束：

- 十个序列位置必须稳定，不能因数字形状不同而漂移；
- 五档品质只改变材质、色彩、反射和宝石表现，不改变身份几何；
- 不同途径可以拥有不同的承接语言，但同一路径内部必须保持可复用；
- 圣徽必须能够独立替换、净底、复用和逐枚验收；
- Agentic 生图不能被当作像素级几何锁定工具；
- 透明孔洞、接触阴影、边框纹理和圣徽本体不能出现重复绘制或责任不明。

此前存在两种容易混淆的思路：将承托完全随圣徽生成，或只在母版中留出空白位置、之后把圣徽直接贴上去。前者造成位置和承接形态漂移，后者造成圣徽悬浮、缺少受力关系。需要把“结构接口”和“可替换符号”拆开。

## Decision

采用三层职责明确的 `EmblemDock` 架构：

```text
主体与背板
    ↓
母版框架 FrameCore
    ↓
EmblemDock：固定嵌座、暗腔、承托边缘、遮挡规则
    ↓
圣徽本体 EmblemAsset：途径母标识 + 艺术数字 + 自身材质
    ↓
确定性合成：定位、接触阴影、前缘遮挡与门禁
```

### 1. 母版拥有结构

母版框架必须预置一个固定的圣徽嵌座，而不是只留一块没有语义的空白。母版或途径载体层负责：

- 圣徽的唯一几何区域、锚点和最大可见框；
- 嵌座暗腔、底托、承托边缘和与框肩的过渡；
- 圣徽安全区、序列数字孔洞保护区和姓名/宝石禁入区；
- 材质厚度、主光向、接触反射与遮挡顺序；
- 五档品质对应的嵌座材质派生规则。

嵌座是框架的结构接口。它可以具有途径专属的形状语言，例如愚者的帷幕收束，但不得由每个数字圣徽临时改变外轮廓。

### 2. 圣徽拥有识别形体

圣徽仍作为独立、可替换的透明资产保存，负责：

- 途径母标识与序列数字的 Agentic 融合；
- 数字骨架、镂空、面具/符号轮廓和自身浮雕；
- 自身的材质、切面和局部高光；
- 受限范围内的自身接触暗边。

圣徽不得携带完整边框、完整承托、任意大小的外部底板或伪文字。圣徽的透明画布不参与定位，定位依据是净底后的可见字形边界。

### 3. 合成器拥有装配

确定性合成器负责：

- 按 `EmblemDock` 的固定锚点装配圣徽；
- 对每枚数字独立测量可见边界并计算变换；
- 生成统一的接触阴影、前缘遮挡和局部反射；
- 验证圣徽没有越出允许域、侵入姓名/宝石区或穿过自身镂空；
- 记录输入摘要、变换、实际像素和门禁结果。

Agentic 生成可以探索嵌座外观和圣徽风格，但正式结构只能来自冻结的母版与结构化接口。完整框徽参考图只能作为生成附件和视觉参考，不能替代 `EmblemDock` 的几何合同。

### 4. “孔洞”采用视觉嵌孔，不做默认穿透孔

这里的“圣徽孔洞”定义为具有深度的视觉嵌座，而不是让主体插画透过的真实透明洞。嵌座使用暗腔、承托面和边缘遮挡制造嵌入感；只有明确的多层实体导出需求才允许真实 alpha 穿透，并必须另行声明接收层和遮挡规则。

这样可以防止主体背景纹理穿透圣徽、破坏对比度，也能让五档框在不同人物场景中保持相同的身份识别质量。

### 5. 每个像素区域只有一个结构所有者

结构所有权固定如下：

| 区域 | 唯一所有者 | 禁止重复拥有 |
| --- | --- | --- |
| 外轮廓、框肩、底部轨道 | `FrameCore` | 圣徽不得重画 |
| 嵌座暗腔、底托、承托边缘 | `EmblemDock` | 圣徽不得携带完整承托 |
| 途径形体、序列数字 | `EmblemAsset` | 母版不得复制数字 |
| 接触阴影、前缘遮挡 | `Composite` | 母版与圣徽不得各烘焙一遍 |
| 品质材质和宝石派生 | `QualityMaterial` | 不得移动结构锚点 |
| 姓名区域 | `NameEngraving` | 不得覆盖钻石或重画姓名底板 |

任何新图层必须声明 owner、z-order、允许域和保护域。出现两个层都绘制同一承托边缘时，拒绝进入正式装配。

## Alternatives Considered

### A. 圣徽自带完整承托，后补到边框

拒绝。每个序列数字会带来不同的底座宽度、阴影、连接角度和视觉重量，难以保持十张卡的固定几何；替换圣徽或换品质时需要重复返工，且最容易出现贴纸感和双重阴影。

### B. 母版只留空白，不制作承托

拒绝。空白区域没有受力、深度和遮挡关系，圣徽只能被当作平面贴片叠加；不同主体背景会进一步放大违和感。

### C. 直接让 Agentic 生成完整框、圣徽、文字和承托

拒绝作为正式生产路径。它适合探索整体气质，不适合提供可测量、可复用、可回归的几何接口；文字错误、孔洞堵塞、位置漂移和框体重绘无法稳定由视觉判断补救。

### D. 母版固定嵌座，圣徽独立装配（本决定）

接受。结构稳定、替换成本低、路径特征可持续、五档可派生，并且能够把 Agentic 的创作优势限制在真正需要创作的区域，把几何与文字交给确定性工具。

## Consequences

### 正面影响

- 同一路径的 10 个圣徽共享一套可测量的安装接口；
- 五档框只需派生材质和宝石，不需要重复设计承托几何；
- 圣徽、框架、姓名和主体可独立返修，缺陷不会扩散到无关层；
- 可以建立明确的 `emblem_dock`、`protected_regions` 和 `ownership` 门禁；
- 视觉嵌入关系由母版提供，圣徽不会因透明留白或外部光晕产生漂移。

### 成本与限制

- 每条途径需要设计并批准自己的嵌座语言；
- 母版几何变更会使下游圣徽定位和完整卡片重新验收；
- 合成器必须支持遮挡、保护域、实际可见 bbox 和确定性回放；
- 旧的“带承托圣徽”研究稿只能作为参考或专用层，不能自动转为公共资产。

## 版本与迁移规则

1. 本决定的结构化合同为 [`production/templates/emblem-dock-interface-v1.json`](../../production/templates/emblem-dock-interface-v1.json)，机器约束为 [`production/schemas/emblem-dock.schema.json`](../../production/schemas/emblem-dock.schema.json)。
2. 原 [`frame-emblem-interface.json`](../../production/templates/frame-emblem-interface.json) 保留为旧接口历史模板，不删除、不覆盖、不把空值解释为通过。
3. 新母版使用新的 `geometry_id`；不得通过拉伸、扭曲或重新测区把旧漂移稿伪装成新母版。
4. 现有 v5 框、已认可的 9–0 圣徽和已批准的克莱恩序列9图像保持原版本及原批准范围；它们不因本 ADR 自动获得 `EmblemDock` 结构批准。
5. 新结构完成后，先做单枚圣徽试装，再做一条途径的 10 个序列，最后才允许扩展到 22 条途径；未通过母版和嵌座门禁时不得批量生图。

## Verification boundary

本次 ADR 与结构化合同落盘，不代表 v6 母版、22 条途径嵌座或新的渲染器已经生成、批准或正式 release。后续实现必须分别报告：合同校验、实际像素合成、视觉观察、用户批准和正式发布状态。
