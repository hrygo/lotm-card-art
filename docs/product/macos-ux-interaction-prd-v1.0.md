## 0. 摘要与范围

### 0.1 一句话目标

把《诡秘世界》从「一本卡牌画册」变成「一间可以回到同一个世界的门厅」：用户打开 App 第一眼看到的是**他的世界现在是什么状态**，而不是一个内容列表。

### 0.2 本 PRD 负责什么

- macOS 客户端的**信息架构**：一级区域划分、导航层级、界面清单与路由。
- 每个界面的**目标、内容构成、交互、状态与空态**。
- **交互契约**：运行时状态机如何映射为用户可见状态；选择、收束、播放、失败降级的交互规则。
- **呈现规则**：状态文学化、位格与叙事尺度的界面表达、Audio First 的交互节奏。
- 平台基线、可访问性、键盘与本地化要求。
- 客户端与引擎的**边界**，以及里程碑与验收标准。

### 0.3 本 PRD 不负责什么

- 故事生成、Canon Guard、Knowledge Gate、Outcome Resolver、Memory Distillation 的算法与协议（属《Story Engine PRD》《Character Engine & Memory PRD》《Canon / Knowledge / Spoiler System PRD》）。
- 音频资产的生产工艺与 Voice Persona 参数（属《Audio Engine PRD》）。
- 卡牌内容生产、六维语义契约与视觉批准（属 `design/` 与 `docs/production-sop-v3.md`）。
- 内容层（Canon、人物、途径、Narrative DNA）的治理（属《Content Pack & Card Integration Spec》）。

### 0.4 术语约定

- **卡（Card）**：`card_id` 唯一的内容载体，可能是人物身份卡、序列原型卡或特殊存在卡。
- **人物（Character）**：`character_id` 标识的存在，可拥有多张身份卡（同一人物的不同时期 / 不同身份切片）。
- **命运（Fate）**：一次互动故事的产品层名称，对应数据对象 `StorySession` / `Episode`。
- **故事书（Story Book）**：一次命运结束后的成品化呈现，对应 `Episode` 的阅读与聆听形态。
- **世界（World）**：用户个人世界状态的集合，对应 `World State`。

## 1. 平台与设计基线

### 1.1 平台基线

| 项 | 要求 | 依据 |
|---|---|---|
| 最低系统 | macOS 26 Tahoe（`MACOSX_DEPLOYMENT_TARGET = 26.0`） | 根 `AGENTS.md` macOS 基线；`apps/AGENTS.md` 开发基线 |
| 语言与架构 | Swift 6.2+，Apple silicon `arm64`，不维护 Intel 与旧系统分支 | 同上 |
| 窗口 | 单主窗口（`WindowGroup`）+ `Settings` 场景；不引入多窗口工作流 | 单用户个人世界，无并排编辑需求 |
| 最小内容尺寸 | 1180 × 760；默认 1280 × 860 | 现有客户端行为，保持 |
| 材质 | 系统组件优先；自定义材质用 `glassEffect` / `GlassEffectContainer`，遵循系统窗口、工具栏、导航、搜索约定 | 根 `AGENTS.md` |
| 导航 | `NavigationSplitView` + 系统 toolbar / search 语义 | 现有客户端行为，保持 |
| 暗色 | 默认深色（档案馆材质语言），不做浅色变体 | 现有视觉基线；浅色化属未来独立设计课题 |
| 联网 | 默认**完全本机**；唯一远端调用是 loopback SpeechRail（`127.0.0.1:8201`） | `apps/AGENTS.md` |

### 1.2 体验目标

母 PRD §29 的成功标准在界面上必须**可观察**，本 PRD 把它们翻译成界面条款：

| 母 PRD §29 感受 | 界面必须做到 |
|---|---|
| 「这个世界记得以前发生过什么。」 | 世界首页第一屏展示世界时间、世界线、最近事件与未解决事件；事件不是装饰，可点入查看它影响了谁、哪个地点 |
| 「这个人物真的认识以前遇见过的人。」 | 人物页展示关系与关系变化来源（哪一次命运造成），不只展示静态设定 |
| 「这是奥黛丽，但这是我这个世界里的奥黛丽。」 | 人物页把 **Canon 事实**与**本机经历**分区呈现，两个来源在视觉上不混淆 |
| 「上一段故事发生的事情，这一次仍然存在。」 | 故事书保留命运记录、秘密与已写入世界的结果；再次进入同一人物时这些内容仍可见 |
| 「即使没有故事正在播放，我仍然感觉这个世界存在。」 | 世界首页在没有任何进行中命运时仍然是有内容的页面（时间、未解决事件、人物近况），不是空白等待页 |

### 1.3 设计原则（UI 层可执行版）

1. **世界先于故事**：一级入口是「世界」，不是「开始生成」按钮。
2. **角色先于剧情**：任何一段文本都能回答「这是谁在说、他知道什么」；叙述视角归属在界面上可见。
3. **数值不出现在主叙事界面**：灵性、暴露、污染等只以文学化状态提示出现（§4.3）。
4. **不制造 RPG HUD**：不出现血条、经验条、装备栏、数值面板、任务列表式 UI。
5. **每一个重要选择都必须产生真实状态变化**：选择前的代价与选择后的状态变化都要在界面上可读（§4.2）。
6. **故事结束，世界不结束**：结局面板必须给出「这次留下了什么」，并保留回到世界的路径。
7. **诚实呈现**：未核验、示例、待确认内容必须在界面上有一致的标记语言，不用界面精致度冒充内容正确性。
8. **不空操作**：未实现的入口必须明确置灰并说明原因，不放置无效按钮。

## 2. 信息架构

### 2.1 四个一级区域（母 PRD §19）

```text
诡秘世界（主窗口）
├── 世界        World Home        世界状态入口：时间 / 世界线 / 事件 / 正在进行 / 未解决
├── 卡牌        Cards            收藏与设定：画廊 / 我的收藏 / 候选收藏 / 愿望清单 / 途径
│     └── 卡牌详情                身份、六维回读、声音、故事 → 开启命运
│           └── 命运生成           可见种子 → 编织命运
│                 └── Story Player 讲述 / 抉择 / 收束
├── 人物        Characters       存在视角：人物档案 / 身份卡 / 关系 / 经历
└── 故事书      Story Book       已成历史：命运记录 / 秘密 / 关系变化 / 世界影响 / 阅读 / 聆听
```

四个区域是**并列一级**，不是流程步骤。用户可以从世界进入人物，从人物进入故事书，也可以从卡牌直接开启命运。

### 2.2 全局导航规则

- 侧边栏第一段固定为四个一级区域；第二段是**当前区域的局部导航**（卡牌→收藏分栏与途径；人物→人物列表；故事书→命运列表；世界→无二级列表，世界首页自带分区）。
- 主区域（detail 列）只承载一个内容上下文；切换区域时保留该区域上一次的选中项（每个区域独立记忆选中项）。
- 任意界面下 `⌘1`–`⌘4` 直接切换一级区域；`⌘[` 返回上一级（卡牌详情 → 画廊；人物档案 → 人物列表；故事书详情 → 命运列表）。
- 搜索（系统 `.searchable`）作用于当前区域的列表：卡牌区域匹配卡名 / 序列 / 人物；人物区域匹配人名与途径；故事书匹配命运标题与主角。
- 状态栏信息归位：进行中的命运在侧边栏底部持续可见（一句话＋继续入口），不随区域切换消失。

### 2.3 界面清单与路由

| # | 界面 | 区域 | 进入方式 | 主要数据对象 |
|---|---|---|---|---|
| 1 | 世界首页 | 世界 | 启动默认 / `⌘1` | World State、WorldEvent、Episode、Character |
| 2 | 事件详情 | 世界 | 世界首页事件行 | WorldEvent |
| 3 | 卡牌画廊 | 卡牌 | `⌘2` | Card |
| 4 | 卡牌详情 | 卡牌 | 点选卡 | Card、Character、KnowledgeFact |
| 5 | 命运生成 | 卡牌 | 卡牌详情「开启命运」 | StorySeed（可见字段）、Card、Character |
| 6 | Story Player | 命运 | 命运生成「编织命运」 / 继续进行中的命运 | StorySession、Choice、StateDelta |
| 7 | 人物列表 | 人物 | `⌘3` | Character |
| 8 | 人物档案 | 人物 | 点选人物 | Character、Relationship、Memory、Card |
| 9 | 命运列表 | 故事书 | `⌘4` | Episode |
| 10 | 命运详情（阅读 / 聆听 / 记录） | 故事书 | 点选命运 | Episode、NarrativeBlock、Secret、WorldEvent |
| 11 | 设置 | — | `⌘,` | 本机配置（SpeechRail、Spoiler Profile） |

### 2.4 引导与首次运行

- 首次运行不进入空画廊，而是进入世界首页，并显示「这个世界还是空的」+ 一句引导：「从一张卡牌开始，让它进入这个世界。」
- 引导主线：世界首页 → 卡牌画廊（收藏区）→ 卡牌详情「开启命运」→ 编织命运 → Story Player → 结局 → 故事书 → 回到世界首页（此时首页已经因为这次命运而不同）。这条主线就是母 PRD §27 的核心闭环，也是本 PRD 的验收路径。

## 3. 界面规范

以下逐屏规范共用一套状态词汇：**空态**（无数据）、**就绪**（可操作）、**进行中**（有任务在跑）、**失败**（有错误且需用户处理）、**降级**（功能不可用但内容仍可读）。

### 3.1 世界首页（母 PRD §19.1）

**目标**：打开即确认「我回到了同一个世界」。不是内容平台首页，不出现热门、排行、社区动态。

内容分区（自上而下，全部只读，点击进入对应详情）：

1. **世界状态头**：世界名、世界时间（例：「第五纪 · 某年十月」）、当前世界线标记、数据状态标记（示例 / 已核验）。
2. **最近发生的重要事件**：3–5 条，每条给出标题、时间、地点、影响级别（个人 / 关系 / 地区 / 世界）。影响级别用文字标签，不用进度条或星级。
3. **正在进行的命运**：至多 1–3 条，给出主角、地点、当前处境一句话与「继续」；没有进行中命运时显示「此刻没有人正在经历什么」＋「从卡牌开始一段命运」。
4. **最近活跃人物**：2–4 位，给出人物名、途径与序列、上一次出现的时间与地点。
5. **未解决事件**：以问句或短语呈现（「某处的那桩案子还没有结论」），点入可看到它出现在哪些命运里。
6. **重要地点变化**：只列出真正被写入世界状态的地点变化。
7. **最近完成的故事**：2–3 本，直接进入故事书详情。

**空态**：全部七区为空时，显示引导文案与「前往卡牌」主按钮；不显示假数据、不显示骨架屏。

**失败态**：本机数据读取失败时，显示可重试错误块，明确说明是「本机世界状态读取失败」，不欺骗为「世界为空」。

**禁止**：任何形式的推荐位、点赞、分享、社区、排行榜；任何来自网络的世界内容。

### 3.2 卡牌画廊（沿用 M1，扩展）

**目标**：收藏、设定与视觉欣赏，并作为世界入口。

保留：画廊 / 我的收藏 / 候选收藏 / 愿望清单四个分栏、途径过滤器、搜索、卡片网格、状态标签。

新增要求：

- 卡片上标注该卡在**本机世界的经历状态**：「未进入世界」/「有一段进行中的命运」/「已有 N 段历史」。这一标注与内容核验状态是两个独立维度的标签，不得合并成一个。
- 序列卡与人物身份卡在同一网格中共存，但身份类型必须有文字标签（`身份卡` / `原型卡` / `序列之上`）。
- 卡片集合的**分母**口径沿用客户端约定：卡槽基线不是上限，不出现「x / 220」这类把卡槽当收藏上限的进度。

### 3.3 卡牌详情（母 PRD §19.2）

结构（沿用 M1 两栏布局：卡面舞台 + 信息栏）：

- 左：卡面（原生画布，不做 2K / 4K 中间态转换）。
- 右：身份面板（姓名、身份类型、途径与序列、层级、六维语义回读）、声音面板（播放 / 台词 / 失败降级）、**命运入口区**。

**开启命运**（本节新增的核心交互）：

- 主按钮措辞随卡类型变化：
  - 人物身份卡 → 「进入〈人名〉」；
  - 序列原型卡 → 「以该序列创造一个人」；
  - 特殊存在卡 → 「以祂的尺度介入世界」。
- 按钮下方一句话说明将继承什么（例：「将继承该人物在这一时间点的身份、能力边界与已知信息。」）。
- 满足条件时才可点击；不满足时按钮置灰并给出原因（例：「这张卡缺少该时间点的人物档案，无法进入人物视角。」）。
- 已有进行中的命运时，主按钮变为「继续这段命运」，并给出「另起一段」次按钮；同时出现的命运数量上限为 3，达到上限时仅允许继续或收束。

### 3.4 命运生成（母 PRD §19.3）

**目标**：让用户看到「即将进入什么」，同时不泄露幕后真相。

结构：

- 卡面继续作为视觉主体（缩小但保留在位）。
- 可见种子，最多四条，逐条淡入：时间 / 地点 / 异常 / 压力。文案是叙事语言，不是参数（「一个已经死去却仍拥有未来的人」而不是「事件类型：悖论」）。
- 主按钮：「编织命运」。次按钮：「换一个入口」（重新生成可见种子）。
- 明确声明：「这里只显示你已经能察觉的部分；真相将在过程中展开。」

**禁止**：不显示完整 Story Seed；不显示秘密数量、NPC 目标、承诺账本、结局集合、难度或时长预计（秘密数量只在结束时以「已揭开 4 / 7 个秘密」出现，属故事书）。

**进行中**：编织期间显示「正在编织命运…」，同时列出正在准备的层次（世界状态 / 人物档案 / 知识边界 / 声音），不使用虚假进度百分比；任一层次失败时给出可重试错误与「仍然进入（降级）」选项。

### 3.5 Story Player（母 PRD §19.4）

**目标**：以音频为主体、以文字为骨架的互动叙事界面，不是聊天窗口。

构成（顺序即视觉层级）：

1. 卡面 / 人物视觉主体（常驻，不遮挡文字）。
2. 当前章节位置（章节名 + 第几段），不使用「第 X 回合」。
3. 叙事正文（角色第一人称讲述为主体；旁白只用于时间、空间、镜头转换，并在视觉上与角色讲述区分）。
4. 音频控制：播放 / 暂停 / 继续 / 停止 / 重播 / 上一段 / 下一段；音频缺失时保留文字稿并显示失败原因。
5. **文学化状态提示**：条形式提示，最多两条同时显示（「你的灵性已经接近枯竭。」「有人开始怀疑你的真实身份。」）。
6. **命运选择**：2–3 个选项（母 PRD §13.2 默认三个），每个选项给出**策略标签与主要代价**（例：「重新进行占卜 · 信息优先 · 灵性消耗」）。选项必须代表不同策略，禁止同义改写。
7. **收束命运**：次级按钮，任何合适节点可用；点击后进入收束确认（「接下来将处理当前主线，不再引入新的主要冲突」）→ 确认后进入 Closure 流程。

**选择交互规则（母 PRD §8.3、§13.3–§13.4）**：

- 选择是**建议**不是命令。界面上不得出现「执行」「命令」等措辞；提交后必须呈现「人物如何理解并执行（或部分偏离）你的建议」，偏离必须有自然原因并在文本中给出。
- 每个选择在提交后必须产生至少一项可见变化：后续信息、时间、关系、风险、暴露、状态、NPC 行为、场景进入、结局条件或世界事件。
- 选择提交后进入「正在发生」状态（短暂），期间禁止重复提交；解析失败时明确说明「这次选择没有生效」并提供重试，不伪造已发生的结果。

**收束与结局（母 PRD §14.3–§14.4）**：结局面板必须给出结局类型（真相 / 胜利 / 幸存 / 代价 / 失败 / 逃离 / 错误真相 / 开放 / 失控 / 死亡之一）、这次命运的代价与留下的痕迹，以及两个出口：「阅读这段命运」（故事书）与「回到世界」。

### 3.6 人物（新增区域）

**目标**：让「人物」成为可从任意角度回访的存在，而不是卡的附属信息。

**人物列表**：每位人物一行/一卡，显示姓名、途径与序列、存在类型（原著人物 / 原创人物 / 特殊存在）、身份卡数量、最近一次出现的时间与地点、当前是否有进行中的命运。

**人物档案**分四段：

1. **身份切片**：这个人物的全部身份卡（例：同一位克莱恩的序列 9 廷根时期身份卡与序列 0 愚者先生身份卡），点入卡牌详情；明确标注「同一个人的不同时期与身份」。
2. **本机世界的经历**：这个人经历过的命运列表（时间倒序），每条给出代价与结果摘要。
3. **关系**：关系项（信任 / 恐惧 / 尊重 / 亲近 / 敌意 / 债务 / 共享秘密 / 上次相遇），每项标注**来源**（原著事实 / 本机经历）与最近变化的那次命运。
4. **他/祂知道什么（知识边界）**：只列出这位人物**本人**知道的事实，并标注范围（公开 / 社交 / 组织 / 教会 / 途径 / 高序列 / 秘密 / 禁忌 / 宇宙）；不展示用户知道而人物不知道的事实（母 PRD §9.1）。

**代词规则**：真神及以上（序列 0、天使之王、旧日 / 序列之上）作为主体时一律用「祂」，其源质与概念同样用「祂」（见 D15 与 `docs/card-narrative-contract.md`）；人物页的界面文案同样遵守，不因是 UI 字符串而降格。

**空态**：无本机经历时，明确写「这个人还没有在你的世界里经历过什么」，不显示占位假经历。

### 3.7 故事书（母 PRD §20）

**命运列表**：以「一本本」的形态呈现，显示封面（卡面缩略）、标题、主角、时间地点、结局类型、状态（进行中 / 已完结）。进行中的命运排在顶部且可继续。

**命运详情**三段式：

1. **阅读模式**：以**实际发生过的叙事块**为主，允许必要过渡文字，但不得在结束后重新改写一篇「差不多」的小说（母 PRD §20.1）。章节按实际顺序排列，不重新编号。段落的来源是**这段命运自己记下的内容**；只有它还没有留下段落时才回退到该卡片的叙事，并在界面上明说来源。**进行中的命运不得展示尚未发生的章节**——没有写到的地方就是空白，不用卡片叙事或模型补写填满。
2. **聆听模式**：复用该次命运已生成的音频，补齐转场与终章；播放控制与 Story Player 一致；缺失段落显式标注「这一段没有留下声音」，不用其他音频顶替。
3. **命运记录与影响**：
   - 命运选择路径（按时间顺序，例：调查尸体 → 隐藏身份 → 相信陌生人 → 拒绝仪式 → 保护受害者 → 开放结局）；
   - 已发现秘密：「已揭开 4 / 7 个秘密」；未发现的秘密**不显示答案**，只保留未揭开的位置感；
   - 关键人物与关系变化；
   - 世界影响：只列真正写入世界状态的结果；每条可点击跳转到世界首页对应事件；
   - Canon 分叉提示：若这次命运产生了世界线分叉，明确标注「从这里开始，历史走向了另一条线」。

**禁止**：不提供「重写这个故事」；不把未揭开的秘密当彩蛋展示；不用统计图表堆砌。

### 3.8 设置

- **SpeechRail**：沿用现有配置界面（本机 loopback、API key 写入仓库外的本机文件、失败保留文字稿）。
- **剧透档位（Spoiler Profile）**：新增。选项为「无剧透 / 第一卷 / 第一部完成 / 续作进度 / 完整设定」。该档位统一作用于图鉴、卡牌详情、人物档案、命运生成与世界事件（母 PRD §9.4）。
- **声音**：播放音量、环境声与旁白的相对音量（母 PRD §18.3 的声音层次），以及「先文字后声音」偏好（见 §4.4）。

## 4. 交互契约

### 4.1 运行时状态机 → UI 状态映射（母 PRD §24）

| Runtime 状态 | 界面表现 | 用户可操作性 |
|---|---|---|
| `IDLE` | 世界首页 / 画廊 | 全部浏览可用 |
| `CARD_SELECTED` | 卡牌详情 | 可开启命运 / 返回 |
| `WORLD_CONTEXT_LOAD` | 命运生成：可见种子逐条淡入 | 可取消 |
| `STORY_GENESIS` | 命运生成：「正在编织命运…」＋准备层次清单 | 可取消；失败可重试 |
| `SEED_VALIDATION` | 同上，文案切换为「正在校准这次命运的边界」 | 可取消 |
| `OPENING` | Story Player：开场叙述 | 播放控制可用；选择未出现 |
| `NARRATING` | Story Player：正文与音频播放中 | 播放控制、收束可用；选择区显示「尚未需要你决定什么」 |
| `CHOICE_READY` | Story Player：选择区展开，音频进入停顿 | 选择 / 收束 |
| `RESOLVE_CHOICE` | 选择已提交，选择区收起并显示「正在发生」 | 禁止重复提交 |
| `STATE_UPDATE` / `VALIDATION` | 状态提示条更新 | 只读 |
| `NEXT_BEAT` | 回到 `NARRATING` | — |
| `CLOSURE` | 收束确认 → 收束叙述 | 可取消收束（回到选择前状态） |
| `EPISODE_FINALIZATION` | 「正在把这件事故入历史…」 | 只读 |
| `MEMORY_DISTILLATION` / `WORLD_UPDATE` / `AUDIO_FINALIZATION` | 分层清单逐项完成 | 只读；单层失败给出局部重试 |
| `STORY_BOOK` | 结局面板 → 故事书详情 | 阅读 / 聆听 / 回到世界 |

**总原则**：机器状态永远翻译成一句人话；错误必须说明「哪一层失败了」以及「现在还能做什么」。

### 4.2 选择交互细则

- 选项数量：默认 3，允许 2（收束阶段），不允许 4 以上（避免菜单式选择）。
- 每个选项的可见结构：**行动 → 策略 → 主要代价**，三者缺一不可。
- 不可执行的选择不得出现；若某策略因人物能力或知识边界不可行，界面可呈现为「〈人物〉不会这样做」的只读说明，而不是可点击后被拒绝。
- 选择结果的呈现顺序：先状态变化（文学化提示条），再叙述文本；不让用户从文本里猜发生了什么。
- 每个选择节点的最大等待：叙述与解析期间持续显示当前阶段，不静默转圈。

### 4.3 状态文学化（母 PRD §19.5）

- 引擎数值（`spirituality` / `exposure` / `danger` / `injury` / `corruption` / `trust` / `suspicion`）**不得**作为数字、进度条或色块出现在叙事界面。
- 允许的呈现：一条文学化提示（「你的灵性已经接近枯竭。」），最多两条同时显示，语气与人物视角一致。
- 数值的完整视图只出现在「诊断」入口（默认隐藏，需要显式开启），与用户叙事界面物理隔离。
- 提示条的出现必须可归因：点击提示可查看它来自哪一次状态变化（哪一次选择、哪一次事件）。

### 4.4 Audio First 的交互节奏（母 PRD §18.1）

```text
环境声 → 人物讲述 → 必要旁白 / NPC → 声音事件与情绪变化 → 人物提出抉择 → 音频停顿 → 用户选择
```

- 选择区在音频停顿处展开；音频未就绪时不得阻塞选择（先文字后声音，声音补齐后可在故事书聆听模式中补听）。
- 用户跳过本段时停止当前音频并推进到选择或下一段；跳过的段落仍保留在文字稿与故事书中。
- 播放失败（SpeechRail 不可用、资源缺失、未批准文本）时：保留文字稿、显示失败原因、不伪造播放成功，并提供「改为安静阅读」。
- 环境声与旁白的相对音量可在设置中调整；环境声不得压过人物讲述。

### 4.5 失败与降级矩阵

| 失败 | 界面行为 | 禁止 |
|---|---|---|
| 世界状态读取失败 | 明确报错 + 重试 | 显示为「世界为空」 |
| 命运生成失败（种子 / 校验 / 上下文） | 分层说明 + 重试 + 返回卡牌详情 | 用半成品命运进入 Story Player |
| 选择解析失败 | 说明该次选择未生效 + 重试 | 伪造已发生的结果 |
| 音频合成失败 | 保留文字稿 + 原因 + 「安静阅读」 | 用其他音频顶替 |
| 文本未通过人工批准 | 不可播放，界面说明「这段内容还在确认中」 | 播放未经确认的台词 |
| 本机资源缺失 | 显示缺失项与补齐指引 | 用程序化占位冒充正式资产 |

### 4.6 命中与反馈（可点区域）

- **可点区域等于可见行**：整行矩形（含圆角外侧、文字右侧留白）都是点击目标；命中区域按布局尺寸声明，不由画出来的背景或文字决定。
- **装饰不参与命中**：悬停描边、焦点环、选中标记、提示文字等只表达状态的图层必须退出命中测试，尤其不得越过控件边界；点在同一行上必须只有一种结果。
- **按下反馈不移动命中几何**：按下时缩放会连同命中区域一起缩小——缩放越狠，行边缘的死带越宽（侧边栏原来的 0.96 在一条 202pt 宽的行两端各留约 4pt 死带，贴边按下会在松手前移出区域）。凡是「整行都可点、边缘也是目标」的可点区域（侧边栏行、列表行）用亮度 / 不透明度等不改变几何的反馈；只有点击目标离边缘足够远的大块瓦片与离散按钮才保留小幅缩放。
- 材质（`glassEffect`）只负责观感：可点行上的材质不接管指针行为，点击仍由该行自己的按钮语义决定。
- 上述四条对侧边栏、列表行与卡片瓦片一致适用；`⌘1`–`⌘4` 与键盘可达性是点击之外的等价通路，不因鼠标可用而省略。

### 4.7 卡图解码与开页面性能

- **解码不落在主线程**：视图 `body` 不得读文件、解 PNG 或做图像缩放。卡图解码一律在后台完成，主线程只做缓存命中与绘制。
  （依据：`NSImage(contentsOf:)` 在 `body` 里创建时不会解码，真正的解码被推迟到绘制——也就是帧提交路径上。实测同一张 1024×1536 PNG 的绘制成本约 23–58ms；画册一屏 11 张即约 290ms 的主线程工作，且每次 `body` 重新求值都会重来一遍。）
- **每张每档只解一次**：卡图按「网格瓦片档」与「详情大图档」分开缓存；同一张图同时在解时，后续请求等待同一份结果，不重复解码。
- **App 内不放母版**：包内只有「按显示尺寸已经做好的成片」，每一档都在打包时从 `artifacts/**` 的母版生成（落点是 `tools/production.py stage-app-resources`）；运行时**不做任何图像处理**——不缩放、不重编码、不读 PNG 母版。母版与交付规格不变。
- **档位由打包侧定义且不得低于显示需求**：档位写在 `tools/production.py` 的 `APP_IMAGE_TIERS`（当前 tile 长边 1200 → 800×1200、hero 长边 1536 → 1024×1536，只缩不放）；任何一档低于 `APP_IMAGE_DISPLAY_MINIMUM_LONG_EDGE`（960px，由 320×480pt 卡面 2x 推出）即判错。改档位要同时改这里的口径与 QA 记录，不允许只在客户端里改显示尺寸。
- **详情大图不降采样**（硬约束）：打开单卡时看到的像素必须与源图一致。落地方式是「hero 成片就是显示需要的尺寸」——母版长边不超过 1536 时，hero 与母版**同像素**；客户端读到的就是它的原生分辨率，不再有任何运行时缩略图上限。瓦片档同样读自己的成片（800×1200），比降采样前的实际解码尺寸更大。
- **列宽上限与瓦片档一致**：§3.2 的卡片网格，列宽上限取 `albumTileMaxDisplayWidth`（400pt = 瓦片成片 800px ÷ 2）。上限写宽了，超宽窗口会把瓦片拉过成片像素、卡面变糊。打包侧测试会反查这两个数字是否自洽。
- **缓存按字节限流 + 响应内存压力**：同一张卡两档常驻内存差约 10 倍，两档都按字节成本限流（tile 96MB / hero 128MB）；收到系统内存压力警告即整体丢弃解码结果（重解一张瓦片只需几毫秒）。卡图变多时不得改成按张数限流。
- **预热**：进入 App 后即预热画册要用的卡图（先瓦片档、后详情档）；**两档的预热张数都设上限**（当前 24），超出可视范围的部分改为滚动到跟前时按需后台解码——预热全部卡图只会让解好的图被成本限流立刻淘汰，而常驻内存也不该随卡数线性增长。
- **Liquid Glass 的合并渲染**：页面上多个 `glassEffect` 应放进同一个 `GlassEffectContainer` 合并渲染；**容器的 `spacing` 必须小于内部布局间距**，否则相邻玻璃在静止状态就会融合成一片（例：瓦片间距 16pt 时容器用 8pt）。Apple 文档明确「容器 spacing 大于内部布局 spacing 会导致静止融合」，这条属于视觉正确性，不是调优。
- **降级不摆假图**：解码未完成时保留卡面底色，解码失败才回退到程序化卡面；不用占位图冒充正式资产。
- **档位与格式的选型依据**见 `docs/research/2026-09-15-client-image-delivery-and-decode-research.md`（打包时生成显示尺寸衍生档、母版不进 App、瓦片宽度上限与档位公式的实测数据）。该研究稿本身是建议、不是本 PRD 的规范；它的第一步已由 **D23** 落地，档位取值以 D23 与 `APP_IMAGE_TIERS` 为准（研究稿建议的 640/800 档低于改动前的实际解码尺寸，故未采用）。**有损编码是可见变化**：当前成片是否可接受，须由用户做 1:1 对比后判定（D16）。

## 5. 视觉与动效

### 5.1 视觉语言

- 沿用现有「秘史档案馆」材质语言（皮革、黄铜、羊皮纸、以太青碧；见 `ArchiveTheme`）：深色沉浸、暖色正文、金属仅用于结构与强调。
- 层级色只用于**序列层级标签**（低序列 / 中序列 / 圣者 / 天使 / 真神），不得用于状态、按钮或叙事状态；状态色与层级色互不复用（现有测试已锁这条，新增界面必须延续）。
- 「世界」区域可以更克制：世界首页以时间与事件为主，不做卡面风格的华丽装饰；故事书以「卷宗 / 纸张」为主；Story Player 保持音频优先的安静。

### 5.2 动效

- 动效只用于表达状态变化（种子淡入、音频波形、抽屉展开），不用于装饰性漂浮与炫技。
- 遵循「减少动态效果」（`accessibilityReduceMotion`）：所有位移动效降级为交叉淡入，音频波形静止为静态条。
- 关键状态转换（进入选择、结局）不使用弹跳或夸张缓动。

### 5.3 位格与叙事尺度在界面上的表达（母 PRD §5.5、§16.2）

- 选择措辞随尺度变化：人的尺度是「走左边还是右边」；天使尺度是「哪些锚与命运会被牵动」；真神与序列之上是「是否回应、是否让某种因果进入现实」。
- 界面元素不随位格增加（不给高位叙事加更炫的 HUD）；差异体现在**选择措辞、代价表述与结局类型**上。
- 高位存在的界面文案使用「祂」并保持距离感；不把高位存在写成可闲聊的角色扮演对象。

## 6. 可访问性、键盘与本地化

- **键盘**：`⌘1`–`⌘4` 切换区域；`⌘,` 设置；`⌘[` 与 `Esc` 返回上一级；空格播放 / 暂停；`→` / `←` 下一段 / 上一段；选择项 `1` / `2` / `3` 可直接提交。
- **VoiceOver**：卡面、事件、关系、秘密、选择项均提供语义标签；叙事正文按段落可读；状态变化不只靠视觉提示传达。
- **对比度与字号**：界面元信息不小于 13pt，叙事正文不小于 17pt（沿用故事面板现状）；状态提示与代价说明不得仅依赖颜色。
- **减少动态效果**：见 §5.2。
- **本地化**：简体中文为首发语言（`zh-Hans`）；界面字符串走本地化资源，不硬编码在视图中；人物专名保留既定拼写。
- **代词与称谓**：界面与叙事统一遵守 D15（真神及以上用「祂」），不因文案位置（按钮、提示、列表）而例外。

## 7. 数据与分层边界

### 7.1 客户端与引擎

- 客户端是内容与世界的**运行时投影**：只读展示 + 用户交互，不生成内容、不裁定 Canon。
- 按 D17，World / Character / Story / Audio 引擎**不属本仓库实现范围**。当前阶段客户端使用**合成示例世界（fixture）**驱动世界 / 人物 / 故事书三个区域；示例数据必须在界面上带一致的状态标记（§7.2），且**不写入**任何卡牌源文件、批准记录或 `artifacts/**`。
- 客户端不得把用户收藏、笔记、密钥、缓存或世界状态写回公开卡牌源。

### 7.2 状态标记语言

界面上所有内容必须具备可区分的来源标记：

| 标记 | 含义 | 界面表现 |
|---|---|---|
| 已核验 | 通过内容核验的事实 | 无额外装饰，可直接陈述 |
| 待确认 | 内容尚未核验 | 标签「待确认」，与卡牌使用同一套状态标签 |
| 示例 | 用于验证界面的合成示例世界数据 | 世界 / 人物 / 故事书顶端持续可见的「示例」标记 + 说明 |
| 本机经历 | 用户本机世界中生成的历史 | 标签「本机经历」，与 Canon 事实分区 |

### 7.3 与卡牌内容的接口

- 客户端通过经过审核的卡牌内容包读取卡牌；`card_id` / `slot_id` / `character_id` / `identity_slice_id` 的职责分离沿用 `apps/AGENTS.md` 约定。
- 叙事文本播放必须通过人工批准摘要校验；未批准内容不可播放（既有门槛，新增界面继承）。
- 世界与故事书中的「秘密」「世界影响」等对象不得回写进 `card.json` / `canon.json`。

## 9. 验收标准

### 9.1 机器可断言（客户端测试）

1. 四个一级区域存在且可切换；每个区域独立记忆选中项。
2. 世界首页七个分区在示例数据下均渲染；无数据时为空态而非假数据。
3. 卡牌详情的命运入口按钮措辞随身份类型变化；不满足条件时置灰并给出原因。
4. 命运生成界面**只**暴露可见种子字段；不包含秘密数量、NPC 目标、结局集合等幕后字段（以模型字段可见性断言）。
5. 故事书详情包含命运记录、秘密计数、关系变化、世界影响四类信息；未揭开秘密不包含答案文本。
6. 状态数值（灵性、暴露等）不出现在叙事界面的可见字符串中。
7. 未批准文本不进入播放列表；音频失败时文字稿仍存在。
8. 用户可见文案不包含内部术语（沿用既有「禁止内部术语」测试口径）。
9. 阅读模式优先使用这段命运自己的段落；回退到卡片叙事时界面明示来源；进行中的命运不出现卡片完整章节，也不出现没有发生过的事件。
10. 卡图档位与打包：每张已登记卡图每档都有成片、母版 PNG 不进包、档位不低于显示需求下限、只缩不放（母版不超过档位时详情档与母版同像素）、成片总体积显著小于母版、记录双向绑定源图与成片 sha256；列宽上限不超过瓦片档的显示覆盖；客户端每档只读自己那一份文件且两档不解析成同一文件。
11. 卡图缓存：同一张图同一档只解一次（含并发请求与预热/按需重叠的情况）；丢弃缓存后重新解码而不是留下空结果。

### 9.2 人工观察（不可由机器冒充）

1. 世界首页第一眼是否给用户「回到同一个世界」的感受。
2. 人物页能否在不看名字的情况下通过经历与关系认出这位人物。
3. 选择项是否代表不同策略（而非同一行为的不同措辞）。
4. 是否出现 RPG HUD 感（数值、进度、任务列表）。
5. 高位存在的界面是否保持了位格感。
6. `.app` 实机运行与 VoiceOver 抽查。

---

## 10. 不做清单

- 不做社交、联机、多人世界、排行榜、社区动态。
- 不做 RPG 数值界面（血条、经验、装备、任务列表）。
- 不做聊天式 AI 对话界面（不把叙事降级为对话框）。
- 不做内容平台式首页（推荐、热门、算法推荐位）。
- 不做多窗口工作流、不做 iPad / Windows 布局分支。
- 不在叙事界面显示引擎数值或调试信息。
- 不改写已结束的命运；不为迎合用户重写世界历史。
- 不把机器门禁通过与示例数据冒充内容完成或视觉批准。
- 不把「220」当收藏上限或世界规模分母。
