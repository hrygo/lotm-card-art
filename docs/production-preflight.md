# 开工、返修与交付检查表

版本：1.0.0。供 Agent 执行当前 SOP 时逐项判定，不是新 CLI 或自动批准机制。只检查本次任务范围；已有授权继续有效，不逐阶段重复索要确认。

## 1. 先确定交付范围

| 本次任务 | 必需产物 | 不默认附带 |
| --- | --- | --- |
| 公共/途径物料 | 原图、结构化输入、来源、工程与视觉结论、复用边界 | 角色故事、声音、整卡发布 |
| 视觉试装 | 本卡身份、当前图层配方、实际合成图、图像检查与待审项 | 完整内容交付、音频、App 接入 |
| 完整人物卡内容 | 视觉交付、问候、口头语、角色故事及各自当前审核 | 新音色注册、声音克隆、App 修改或发布 |
| 语音/应用接入 | 当前请求明确包含的声音或 App 产物及对应检查 | 扩充其他卡、批量生图、自动发布 |

任务记录写明 card/slot/character/identitySlice、交付范围、实际资产版本、当前批准范围及未包含项。只有物料任务不编造角色身份；只有视觉试装不将“完整人物卡”写成已完成。

## 2. 工具能力预检

调用前将“任务需要的能力”与当前工具实际能力逐项匹配，检查精确接口、输入示例和最近有效验证记录：

- 五档任务的 quality 从色表解析；编译接受 saint/angel 不代表渲染器也接受。旧四档 all 不能承担新五档交付。
- Agentic 创作、净底、分区材质派生、确定性合成和视觉审核分开。工具不能接收 mask 时，不在 prompt 中声称已经硬锁像素。
- 模板、源码、可执行程序和实测输出分别确认。模板填齐只代表输入描述充分；缺少对应实现时保持“待接入”，不重复调用不适配工具试运气。
- 生图前实际打开附件，明确每张是母框、编辑目标、身份还是风格参考。prompt 与 call 只记录实际传递的内容；文字 contracts 不算图像附件。
- 当前任务实际使用的附加 Skill、几何合同与所有 mask 列入 contracts。自动追踪范围以编译器实现为准，不依赖文档之间的链接自动递归收集。

能力不足只阻止依赖该能力的阶段；可继续研究、准备输入与独立内容工作。不得把无法合成的候选标为工程可用，也不自动安装、购买或换服务扩大范围。

## 3. 五档框徽装配准入

装配前由 Agent 检查 `production/templates/frame-emblem-interface.json` 对应的实际侧车；没有数据的项写明确缺口，不填写猜测值、0 或 pass。

1. **共同基线。** 母框、净底徽、姓名、承接件分别有真实文件、摘要与用途。画布尺寸、坐标原点、单位、采样和变换一致；候选与冻结正本分开。
2. **逐枚接口。** 每枚数字有左右框肩接点、徽缘实心接点与接收域。末端隐藏在实心边缘后方，孔洞和眼部镂空属于保护域；不能复制9的参数到其余数字。
3. **比例与姓名。** 徽章按可见字形测量，姓名按笔画本体测量；光晕不参与中心计算。先在缩略图判断人物是否仍为主视觉，再检查原尺寸数字可读性与姓名双轴误差。11.5%只作已接受单卡参考，不作全族常数。
4. **联合材质。** 框纹理、帷幕与两者宝石共用品质锚色、受光方向和反射环境。分别核对纹理 mask、宝石 mask、保护 mask；保护域优先于材质域，重叠冲突先解决。圣徽宝石改色须有具体区域授权。
5. **自然过渡。** 不同材料可有不同粗糙感与暗部，但接触处不出现断色、错向高光或重复阴影。宝石有可辨体色、暗面、折射与局部亮面，不是泛白光团。
6. **可验证输出。** 实际输出层、最终变换与清单一致；按确定性预期检查结构及半透明 source-over 结果。另看深/浅底、单层和整卡，检查灰边、残底、孔洞遮挡与拼贴感。

扩展验证在既有授权范围内进行：先验证低/真神跨度及圣者/天使区分，再检查剩余品质和每个数字。十个序列按五档映射产生十种目标框徽组合，不自动制作五十种组合，也不因同框就免除逐枚检查。

## 4. 文案不是附属占位字段

问候、口头语和故事共用本卡的身份阶段，但各有目的：问候建立关系，口头语提供记忆点，故事通过行动和代价呈现人物。开工时清点，完整内容交付时逐项验收，不能等画面通过后才发现遗漏。

- **口头语：** 符合当前身份的语气；不将拟写当原著，不将一次台词未经核对称为惯常口头禅。同义复述不充作多条内容。
- **故事：** 每章有处境、行动/选择和变化或代价；核对说话视角、时间顺序、剧透边界和当前能力。可与画面主事件呼应，不必每章重复画面描述。
- **可读与可说：** 正文独立可读，不写 TTS 控制词；读音表另存。视觉意向不要求把文案写进插画。
- **批准：** 执行叙事合同的结构检查，用户逐字批准绑定当前摘要。空模板通过结构检查仍是待制作；草稿、已驳回和缺口不得计作已批准内容。
- **声音：** 仅执行本次授权且文案已经批准的条目；不因其他章节仍为草稿就重做已经通过的条目。每段声音还需独立试听与文件登记。

## 5. 有限返修与依赖影响

| 发生变化 | 优先处理 | 保留与重新验收 |
| --- | --- | --- |
| 品质颜色/材质 | 联合处理框、承接件与授权宝石区域 | 保留冻结几何；重合成，复查品质辨识、接触光和最终图 |
| 徽章外形、数字或接点 | 重测该枚接口与孔洞保护 | 不沿用旧接触域；场景仅在遮挡/安全区受影响时返修 |
| 姓名文字或字形 | 核对身份，重做对应姓名层并测中心 | 不为迁就姓名移动整个姓名牌；复查最终图和身份相关文案 |
| 故事正文、来源或身份阶段 | 重算受影响条目摘要，重新逐字审核 | 旧声音不用于新正文；无视觉语义变化时不重画人物 |
| 仅 SOP/Skill 修订 | 比较新旧要求及影响，保留真实历史记录 | 当前门禁仍按现有摘要规则执行，不补写旧哈希伪造一致 |

每次返修只改变明确变量；记录失败证据、保留层、下一次调整和剩余尝试预算。多次同因失败时先修输入/方法，不换任务 ID 重置预算。旧原图仍存在、旧视觉批准有效于原图、满足当前生产合同，是三种不同结论。

现有编译器使用较粗的依赖摘要，文档修订也会使历史快照失配。上表是工艺影响分析，不是绕过当前 gate 的豁免。迁移时保留旧 call 与批准，新建当前复用评估和版本；禁止把旧图配上并未实际执行的新 prompt 冒充新生成。

## 6. 交付逐项结账

对范围内每项填写：**对象/版本、实际文件、检查证据、批准依据、当前状态、剩余缺口**。未执行不等于通过；范围外标“未包含”，不伪造已完成或无需制作。

完整人物卡分别列出：最终图及分层、准确姓名、框徽、六维语义、问候、口头语、故事；声音和 App 仅在请求包含时列为交付项。机器结构检查、Agent 观察、用户视觉批准、文字批准、试听和正式 release 独立记录。

遗留缺口必须在最终答复中出现。历史回执失配时说明影响的是当前复用/发布资格还是实际文件；没有对应实测，不写“完整程序跑通”“全部资产齐备”或“正式发布通过”。
