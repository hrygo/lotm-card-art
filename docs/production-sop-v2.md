# Agentic 卡牌制作 SOP
版本：2.5.0。工艺依据为本项目实际试装与用户反馈；不是全部程序能力已经实现的声明。圣徽承托架构由 [ADR-001](decisions/ADR-001-emblem-dock-ownership.md) 定稿。本版本补充状态词、资产锁点、缺陷路由和 EmblemDock 硬阈值；既有编译、登记、合成接口见 [v1 工具合同](production-sop.md)，本文件是当前艺术、叙事生产与验收入口。

每次执行先按 [开工与交付检查表](production-preflight.md) 确认任务范围、实际工具能力及准入条件；返修与交付复用该表。检查表是 Agent 执行约定，不是新增自动门禁。

## 1. 两维身份与品质

途径以独特造型、纹理语言和 Agentic 融合圣徽识别；序列以艺术数字识别。品质颜色不取代途径造型。220 是序列覆盖卡位，不是人物卡数量上限；slot、card、character、asset、run 分开标识。

品质唯一配色源是 [quality-color-tokens.json](../config/quality-color-tokens.json)：低9–8、中7–5、圣者4–3、天使2–1、真神0。读取配置中的原始色值，不在各份提示词模板或 Skill 里手工维护第二份色表。事实称谓仍来自 [sequence-hierarchy.json](../config/sequence-hierarchy.json)；圣者、天使在事实分类中仍属于高序列。

主色重点作用于边框纹理、珐琅嵌饰及宝石体色、内部反射。光照允许明暗变化，HEX 不是每个像素的强制值。人物、背景、姓名和整枚圣徽不自动套色；圣徽宝石需要改色时，指定独立区域，不改数字骨架。新配色不通过堆构件、扩大圣徽、增加光晕面积体现升级。

配色采用“识别锚色＋明暗冷暖层次＋受控色相流动”。纹理随凹凸和光向出现深色槽、过渡色与反射色，避免同色平涂；局部珠光或偏色保留该档体色身份，不产生随机彩虹噪声。宝石光亮但不整块泛白：体色暗部、内部折射、高亮切面与小范围火彩共同构成通透感。色彩漂移是允许的艺术表现，几何漂移仍被禁止。宝石外光晕不遮数字和姓名，不以大面积辉光替代切面细节。

## 2. 结构化输入与责任

现有可执行 kind 为 foundation / hierarchy / subject。任务支持 quality（sequence、visual_tier）、contracts（文字侧车路径/摘要）及 subject 的 narrative 引用。五档由配置解析并校验，hierarchy.spec.tier 与 quality 一致；旧 high 仅保留为旧四档任务值。几何/材质扩展使用带版本侧车，由 Agent 转译进 prompt，不假装渲染器已经支持其全部字段。

| 任务 | 精准输入 | 产物与限制 |
| --- | --- | --- |
| 基础材质 | material、lighting、tiling、use_scope；途径Token；实际接收面参考 | 可复用纹理；不含框、人物、身份，不默认需要单独可见背板 |
| 品质框与 EmblemDock | 母框路径/摘要、geometry_id、序列与解析出的品质/色值、嵌座几何、纹理/宝石区域、固定锚点、保护域、光向、侧铭文规格 | 母版拥有固定嵌座与结构承托；五档共骨架；新承接结构单独审定 |
| 融合圣徽 | 途径母标识、该途径数字原图、目标数字、Token、参考角色、目标 EmblemDock 接口 | Agentic 只生成独立圣徽本体；程序净底和定位；圣徽不得携带完整承托或底板 |
| 主体与背景 | slot/card/character、主角准确姓名与证据、当前序列事实、六维转译、完整身份框、人物参考、叙事安全区 | 单次生成完整人物与环境；不复制框、徽、姓名或说明文字 |
| 姓名艺术字 | 身份源路径/字段/摘要、准确文本、姓名内区、字形与效果边界、真实风格参考 | 独立艺术字；逐字审核，按笔画本体双轴居中 |
| 角色叙事 | 共用身份/时间切片、剧透边界、greeting/catchphrase/story、来源与证据、逐字正文、内容摘要及审核 | 独立内容包；不放主插画，不因视觉通过而自动批准 |
| 语音 | 已批准条目及摘要、读音表、已授权音色、情绪/语速/停顿、输出规格 | 独立音频及试听记录；无当前声音授权不调用服务 |

每次任务还绑定：task_id/revision、输入版本/哈希、原生尺寸、输出比例、参考用途、允许写入域、尝试上限及当前次数、失败后回退对象。外部生成参数未暴露时 model/seed 留空，不伪造复现性。

编译器自动绑定 kind 对应 Skill；本次实际使用的其他专用 Skill、几何合同、姓名 brief 和遮罩文件另列 contracts。框徽侧车的结构由 Agent 检查，编译器对任意 contracts 文件只校验路径/摘要；叙事包另有 schema 与内容校验，不混淆这两种能力。

## 2.1 EmblemDock 定稿架构

新母版不再采用“圣徽自带承托后贴入”的路径，也不只留一块无结构的空白。母版框架必须在固定几何区域内提供 `EmblemDock`：视觉嵌孔、暗腔、承托面、接触受光和前缘遮挡；圣徽本体仍以独立透明资产存在，由确定性合成器装配。

```text
主体与背板 → FrameCore → EmblemDock → EmblemAsset → Composite
```

职责不可互换：

- `FrameCore` 拥有外轮廓、框肩、底部轨道和固定结构；
- `EmblemDock` 拥有嵌座暗腔、底托、承托边缘、允许域和保护域；
- `EmblemAsset` 只拥有途径母标识、序列数字及自身浮雕/材质，不得携带完整边框、完整承托、伪文字或任意底板；
- `Composite` 负责固定锚定、接触阴影、前缘遮挡、source-over 顺序与门禁回执；
- `QualityMaterial` 只在授权材质区域改变五档色彩、反射和宝石表现，不移动任何几何锚点。

“孔洞”默认是视觉嵌孔，不是让主体插画透过的真实透明孔。只有明确的多层实体导出任务才允许穿透 alpha，并必须声明接收层与遮挡规则。每个结构像素只能有一个 owner；双重承托、双重阴影、圣徽内置框体和文字层自带不透明姓名底板均阻断装配。

结构化输入与模板使用 [`emblem-dock-interface-v1.json`](../production/templates/emblem-dock-interface-v1.json)，机器约束使用 [`emblem-dock.schema.json`](../production/schemas/emblem-dock.schema.json)。旧 [`frame-emblem-interface.json`](../production/templates/frame-emblem-interface.json) 保留为历史空模板，不作为新结构的准入合同。

## 2.2 状态词与完成判据

状态按证据推进，不按文件夹名称或 Agent 自评推进：

| 状态 | 必须已有 | 明确不代表 |
| --- | --- | --- |
| `study` | 设计意图、参考和观察记录 | 可复用、工程可用或已批准 |
| `candidate` | 实际文件、输入摘要和用途 | 几何/透明/文字门禁通过 |
| `measured` | 结构化合同已填真实尺寸、mask、变换并通过机器检查 | 用户视觉批准或正式发布 |
| `approved` | 用户对具体图像/清单摘要的批准依据 | 其他版本、其他品质或其他途径自动获批 |
| `release` | 所有输入、视觉、内容、来源和发布门禁均绑定当前摘要 | 后续修改仍可沿用旧批准 |

`emblem-dock.schema.json` 的 `status` 只表达嵌座合同状态；人物文案、声音、视觉批准和正式 release 仍分别记录，不能把一个字段当作整卡完成状态。

## 2.3 锁点与依赖方向

生产是有向资产图，不是整卡反复重生。每个锁点通过后冻结上游，后续修复只能从缺陷所属节点向下重放：

| 锁点 | 冻结对象 | 通过后允许的下游工作 |
| --- | --- | --- |
| L0 范围/事实 | card、slot、character、语义与叙事边界 | 视觉意向和资产任务 |
| L1 母版几何 | FrameCore、EmblemDock、姓名/宝石/插画保护区 | 五档材质、圣徽和文字 |
| L2 身份组件 | 每枚圣徽、嵌座接点、五档材质与宝石 | 身份框和主体参考 |
| L3 精确文字 | 途径名、序列名、姓名的透明铭刻层 | 完整身份框 |
| L4 身份框 | 固定框徽文字合成及完整装配摘要 | 主体与背景一体生成 |
| L5 主体场景 | 人物、动作、道具、环境及安全区 | 最终合成与语义检查 |
| L6 交付 | 独立图、分层、回执、批准和 release 状态 | 仅允许创建新 revision |

锁点不是“生成成功”的同义词；每个锁点都要有实际文件、摘要和对应检查证据。几何改变会使 L1 之后全部失效，圣徽外形改变通常只使该枚 L2 之后失效，文字或场景问题不得回退到母版重生。

## 3. 当前生产顺序

1. **核对范围与事实。** 只推进获准的卡或物料。读取当前途径资料、人物身份与语义方案。主体内不放说明文字；六维使用动作、物件、构图等明确线索。抽象意象不冒称传达准确配方、数量或逻辑条件；无法精确传达的内容诚实记录精度。
2. **先冻结母版嵌座。** 为目标途径建立 `FrameCore + EmblemDock`，填写 geometry、dock rect、anchor、socket layers、允许域和保护域；先验证母版内部结构，再进入圣徽和主体生成。母版结构变化必须创建新的 `geometry_id`，不得拉伸漂移稿补偿。
3. **清点独立资产与内容。** 途径母框、嵌座、融合徽、姓名字形与实际净底状态分别核查；完整人物卡同时清点问候、口头语和分章故事，声音仅在请求包含时列为交付项。纯物料任务不强制补角色故事，视觉试装不冒称整卡内容完成。保留认可原稿。原图存在、工程可用、视觉批准、文案批准、声音通过、正式release是不同状态。
4. **装配身份层。** 在固定 EmblemDock 中装入对应序列的独立圣徽，再装配两侧设计铭文和姓名。承托由母版提供，圣徽不携带第二套承托；主体插画内不放说明文字。边框侧铭文属于固定身份层，删除或改字同时检查语义契约，不能只隐藏图层却宣称旧文字cue仍满足。姓名只输出精确字形面罩及由其派生的单层凹刻/倒角/高光，姓名区禁止新增底色、底板、边框或不透明遮罩；姓名必须在母框既有表面上直接铭刻。正式契约尚未同步时保持艺术试装状态。
5. **生成完整场景。** 完整身份框作为真实附件，人物参考另标角色。输出目标是满幅“主体＋背景”，不是一张插画再贴可见背板，也不是模型重画的最终身份框。头部、手、关键道具避开徽章和姓名牌；安静区属于场景的自然环境，不用平面色块填补。
6. **立即真实合成。** 场景裁进载体外轮廓，`EmblemDock` 位于主体与圣徽之间，接触阴影由合成器只生成一次，前缘遮挡由嵌座控制，姓名保持独立透明铭刻；姓名层不得携带任何背景像素，只能落在母框已有姓名表面。旧U形框alpha不等于完整卡牌轮廓。无需求不生独立背板；不得用全图阴影掩盖承托断裂。
7. **逐项观察并有限返修。** 先看实际卡面再定位缺陷。圣徽漂移或侵入孔洞，返修该枚接口；嵌座断裂或受光不合，返修 EmblemDock；主体压徽或材料被姓名牌挡住，返修场景构图；字形错误，返修姓名。保留其余层。每次记录单一主要缺陷、调整变量与剩余预算，不用新任务ID重置同一失败目标的预算。
8. **检验与批准。** 校验文件、实际图层、哈希、变换、像素、alpha、圣徽可见 bbox、孔洞/姓名/宝石交集和姓名中心，观察正常尺寸与局部边缘。用户批准绑定具体最终图和清单，不泛化到全途径、五档配色或正式发布。
9. **依赖一致后扩展。** 新色表、母框、嵌座、Skill或事实源变化，旧快照可能失配。保留旧记录，评估后用新版本重新编译/登记/合成/审核；重新登记已有图不算新生图，也不自动授予新用途批准。

每次生图采用 compile → 读取编译prompt → 传递真实附件 → 内置image_gen → 看图 → 记录call → ingest。实际参数和附件与记录一致。新生成物先pending，批准另有依据。

## 3.1 缺陷路由与最小重放

返修先按缺陷的最小 owner 路由，禁止因为一层失败而整卡重做：

| 缺陷 | 重做节点 | 必须保留 | 需要重新检查的下游 |
| --- | --- | --- | --- |
| 母版轮廓、内部构件、嵌座位置改变 | `FrameCore + EmblemDock`，创建新 `geometry_id` | 旧圣徽、文字和场景仅作历史参考 | 全部 L1–L6 |
| 嵌座材质、暗腔、承托或受光断裂 | `EmblemDock` / `QualityMaterial` | 母版几何、圣徽形体、文字、主体 | L2–L6 |
| 单枚圣徽形体、数字、净底或接点错误 | 该枚 `EmblemAsset` 与接口测量 | 母版、其他数字、文字、主体 | 该枚 L2–L6；若改变场景安全区，再检查 L5 |
| 姓名/途径名/序列名错字、偏心或溢出 | 对应透明文字层 | 母版、嵌座、圣徽、主体 | L3–L6 |
| 主体人物、动作、背景或道具问题 | `SubjectScene` | L0–L4 身份层 | L5–L6 |
| 问候、口头语、故事、来源或身份阶段变化 | 叙事内容包及其摘要 | 无视觉变化时保留 L1–L5 | 文案批准、声音和 release |

任何返修必须记录：观察证据、唯一主要缺陷、修改变量、保留层、受影响锁点和剩余预算。若同一缺陷连续失败，先更换输入或方法；不得换任务 ID 伪造新的尝试预算。

## 4. 框徽衔接与零漂移

自然衔接依赖轮廓连续、厚度、材质、光向与实际遮挡；不是增加一根金属杆就能解决。愚者双侧帷幕收束是历史批准实例中的途径解法；新母版统一遵守 EmblemDock 接口，但不把该具体形态强套给其他途径。

边框纹理、连接帷幕和两者宝石属于同一 material_group，共用品质锚色、光向、反射环境与材质深度；不是所有材质变成同一 RGB。纹理、宝石及保护域分别设 mask，联合检查明暗过渡与接触反射，禁止只改框色而遗留异档承接件。圣徽形状/数字和姓名不进通用调色域；圣徽宝石另有明确区域授权时才派生。

逐枚/逐途径接口以 `production/templates/emblem-dock-interface-v1.json` 建立侧车，并由 `production/schemas/emblem-dock.schema.json` 约束字段：声明像素坐标系、原图摘要、geometry_id、固定变换、嵌座外框、圣徽可见框、锚点、接收层、允许衔接域、圣徽孔洞/姓名/宝石保护 mask。路径字段填写 `{path, sha256, purpose}`，mask 的尺寸和坐标空间必须明确；数值来自真实图层测量。所有被引用的外部 mask/资产同时列入 task.contracts，编译器不递归猜测任意 JSON 中的路径。旧 `frame-emblem-interface.json` 仅保留历史空模板，不得替代新合同。每枚数字仍需独立测量；9 的接点不能照搬到 0/4/7 等数字。

母版先提供固定视觉嵌座：暗腔、承托面、接触受光和前缘遮挡组成连续结构；圣徽只进入该接收域，不携带第二套完整承托。承托末端可以按途径语言接到框肩或圣徽外缘实心区，但不得贯穿数字闭环、眼孔或留白，不得因数字形状临时扩大/移动嵌座。默认不做让主体背景透出的真实透明孔；检查单层、浅/深底与整卡，区分设计上允许的遮挡域与意外残底。依赖原框遮住裁口的定制层，不标为任意位置可复用的公共净底素材。

圣徽按净底后可见字形等比定位，不按透明画布或外部光晕量尺寸。当前愚者单卡11.5%是已接受的实例参数，不是所有途径/序列的最佳常数。跨数字需逐枚检查。姓名按实际笔画边界居中，光晕只参与溢出检查。

冻结结构的来源、内部构件与变换保持固定；材料派生改变允许区域的颜色，不改变位置。Agentic重新生成结构属于新候选，不能拉伸配准后声称零漂移。整卡参考是引导，不是图像工具的硬遮罩保证。

### Agentic 跨品质母框迁移实测

2026-09-14 以 `artifacts/production/fool-five-tier-kit-v5/frame-low.png`（2048×3072 RGBA）作为唯一参考，使用 `production/tasks/fool-agentic-tier-transfer-test-v1.json` 中的精准指令，让 Agentic 生成中序列翡翠框。结果保住了双侧帷幕的大轮廓与翡翠材质创造力，但输出为 1024×1536 RGB、无 alpha，棋盘格已烘焙；统一坐标后的启发式彩色轮廓 IoU 为 0.767128，稳定柱体边界 p95 误差为 2 normalized px，端部/底部最大误差为 247 normalized px。程序版低→中框的 alpha IoU 为 1.0、bbox 完全一致。完整 call 与候选图登记在 `production/calls/fool-agentic-tier-transfer-test-v1.json` 和 `artifacts/production/fool-secondary-asset-kit-v1/studies/fool-frame-agentic-mid-transfer-v1.png`。

结论固定为：Agentic 可进入风格探索、材质研究和局部构件设计；不能直接晋升为 `FrameCore`、母版或正式交付。凡是跨品质结构迁移，必须通过原生尺寸、真实 alpha、固定锚点、外轮廓、内部保护区和像素差异门禁；任一失败只能登记为 candidate-study/reference-only，再由确定性合成器承接其获选的材质语言。

### 愚者侧铭文带与钻石嵌入

愚者 v3 模板把左右侧铭文带固定为相邻柱体主体宽度的 1.5 倍：左 `[38,780,108,280]`、右 `[878,780,108,280]` design px；文字安全区为左 `[50,796,84,248]`、右 `[890,796,84,248]`。铭文带上移至无纹理立柱区，仍然是局部柱状结构，不是整侧面板；左右中心锚点固定，品质档位不得产生偏移。

至少用六字竖排压力样例验收。Agentic 研究稿只定义愚者卷曲端饰、暗槽、浮雕和高光语言；生产层以精确输入字符生成字形，再经 `recess-shadow`、`raised-bevel`、`engraved-face`、`edge-glint` 四层装配。生图伪文字和普通平贴文字都不能成为最终侧铭文。溢出、错字、中心误差超过 1 final px 或文字安全区变化均阻断 gate。

姓名区另有不可豁免的硬规则：中央姓名面板在文字渲染器中必须是零像素背景层；姓名字形以实际笔画墨框为测量对象，横向与纵向都对齐到姓名安全区中心，允许误差不超过 1 final px；只能存在一张精确字形面罩，所有暗刻、倒角和高光均从该面罩派生。`manifest.name.background` 必须为 `transparent-text-layer-only`，否则阻断 gate。

五档钻石研究稿必须进入卡框实际合成。程序按登记的五个 crop 和档位顺序执行黑底连通域净化，生成五个透明 `diamond-{tier}.png` 层，并以锁定可见框 `[101.12,103.68]` design px 放回底部宝石锚点。研究稿、钻石层和边框成品分别留存摘要；钻石五档不与十枚圣徽交叉复制。

身份源像素不变不等于最终半透明边缘RGB不变：最终与既定source-over结果比较，同时排查其下复制框、灰格和色边。几何检查、外观判断、数字回读、品质辨识不能互相替代。

## 5. 门禁与能力边界

| 项目 | 检查 | 不得据此声称 |
| --- | --- | --- |
| 来源 | 实际附件、原图与清单摘要、权限、任务预算 | 文件名正确即已传图 |
| 结构 | 真实层/遮罩/变换、内部构件、EmblemDock owner、实际姓名中心 | 外轮廓相同即内部零漂移 |
| EmblemDock 硬阈值 | geometry displacement = 0；圣徽孔洞/姓名/钻石/域外交集 = 0；可见 bbox 中心误差 ≤ 1 final px；v1 `through_hole = false` | 模板字段齐全即实际嵌座已生成 |
| 透明与衔接 | 解码alpha、孔洞、深浅底、半透明边缘、遮挡域 | 有alpha通道即净底完成 |
| 艺术 | 主事件、途径/数字、品质纹理与宝石、姓名、接触关系 | 色值命中即品质成立 |
| 语义与批准 | 当前可见载体、表达精度、用户批准及图像摘要 | 整卡视觉通过即完整正典核验/release |

五档配置已经采用，活动侧铭文/钻石链路由 `production/symbols/fool-five-tier-kit.json` 的 catalog/manifest 指定版本化工具执行；SOP 不固化易过期的 v3/v4/v5 目录名。旧foolkit工具仍是四档硬编码，不能直接把它的all输出计为新五档。先完成映射与区域实现，再测低档和真神档跨度、圣者/天使区分、其余档与十徽；需另有实施授权，不由本SOP自动生图扩量。

task schema 接受 saint/angel，且要求显式 quality 与配置映射匹配。新任务使用五档值，不以 high 合并圣者/天使。通用 compose 的品质检查和旧 foolkit 仍为四档实现；新五档任务可编译、登记，不代表可用旧 compose 完成新五档装配。渲染器应明确拒绝不支持的匹配，不能静默降档。

当前专用Klein合成器验证确定性图层重建，不是通用自动拆层、通用几何识别或完整release。已接受实例与参数见 [载体附录](pathway-carrier-sop.md)。production 编译器自动追踪当前 SOP、载体/叙事合同、配色、事实层级、任务 Skill 与声明的 contracts；subject.narrative 还追踪内容包和证据。校验同时核对依赖是否遗漏，不仅验证已有列表。图像 references 仍只记真实附件；文字侧车不会自动上传或改写 prompt。

## 6. 角色口头语、故事与声音

完整单卡含独立叙事分支，执行 [角色叙事合同](card-narrative-contract.md)：身份与时间边界 → 问候/口头语/分章故事 → 来源核对 → 逐字批准 → 获授权的声音制作 → 试听 → 可选 App 接入。没有原著证据时保留缺口或明确原创，不拟造“官方台词”。故事以事件、选择和代价刻画角色，不把能力清单当故事。

主体内仍不放口头语、故事或说明文字；可将相关情绪与事件转译进画面。正文与身份/来源共同计算摘要，改字、换阶段或改来源会使旧批准失效。文案、视觉、音频和 release 分别验收，任何一项通过都不代替其他项。没有实际文字/音频时列为待制作，不因模板齐全就声称整卡内容完成。

## 7. 版本与交付

输出独立PNG/sRGB，原生像素与重采样分别记录；一图一牌，预览拼版不替代独立图。画面、分层、任务、call、receipt、配方、程序与当前审核互相绑定。

SOP和Skill更新不回写历史批准。视觉通过记录单独追加，绑定图像及清单哈希；新增配色不会自动重着色或重新批准已接受卡面。重试、工程检查、Agent观察、用户视觉认可、正式release分别记录。仅文档/Skill调整做结构、引用、合同一致性与相关依赖验证；代码变更再执行相应行为测试及项目回归。
