# AI时代《诡秘之主》成神途径卡牌的可控作图实践

研究日期：2026-09-13

研究范围：为本项目已经确定的“22条途径 × 10个序列”的卡牌系统，研究如何同时实现途径高辨识度、序列高辨识度、四档层级差异、人物插画自由度、精确中文信息和 2:3 高清交付。

结论性质：本文是对现有项目规则和公开技术资料的研究性建议。它不是原著事实补充，也不等于已经批准新的正式卡面或新的模型、工具和授权方案。

## 结论先行

在本项目的约束下，最佳实践不是寻找一个“最会画卡牌”的模型，而是采用**角色分离的混合管线**：

1. 用项目 JSON、证据记录和六维语义契约决定“这张卡必须表达什么”。
2. 用 SVG / 矢量图形和参数化规则决定途径标识、艺术化序列数字、层级外框和文字安全区。
3. 用受控生成模型只负责卡面中央的插画、空间、材质和氛围，不负责最终中文、最终徽记或最终数字。
4. 用姿态、边缘、深度、分割、参考图和局部蒙版控制生成，而不是只写长提示词祈求模型记住系统规则。
5. 用非破坏性图层完成合成、修复、排版和高清导出；最终的精确文字与核心识别标记在生成之后落版。
6. 用工作流、种子、模型版本、参考资产、蒙版、原始像素和最终像素记录保证可复核；用人工盲测而不是 JSON 检查替代视觉审核。

一句话概括：**AI 生成“世界与事件”，设计系统生成“身份与秩序”，排版系统生成“准确的信息”。**

这套分工直接对应本项目最难的三个问题：

- 途径和序列标识必须像一个可学习的符号系统，而不是每张图随机出现的装饰；
- 同一个人物可以出现在多张不同序列卡上，但每张卡仍然必须是独立的身份—扮演—能力—魔药—晋升—限制表达；
- 220 个卡位并不等于 220 个角色，不能用“一个角色训练一套风格”的思路替代卡位建模。

## 1. 研究对象和已确定的项目约束

本研究以项目内已经存在的设计依据为边界：

| 已确定目标 | 对作图系统的实际要求 |
| --- | --- |
| 22 条途径 × 序列 9–0，共 220 个正式卡位 | 需要稳定的批量系统，但不能把 220 张误当作 220 个独立人物；`card_id`、人物、途径、序列必须分离。 |
| 途径是第一维、序列是第二维 | 任意缩略图排列中，观察者都应能先后回读“哪个途径、哪个序列”。 |
| 途径标识和序列号融合 | 需要一个可拆分维护、但视觉上成为整体的复合标记，而不是普通徽章加普通数字。 |
| 不使用 0–9 导轨 | 序列信息要由每条途径自己的 0–9 艺术数字语法表达，不能靠通用进度条。 |
| 不展示机械的“序列 01 / 序列 09” | 画面可以保留准确的序列名称，如“心理医生”，但数字使用艺术化字形或复合标记；准确名称作为独立文字层。 |
| 低序列、中序列、高序列、真神有不同 UI 特点 | 层级必须改变宏观结构、边框、标题区、空间关系或材质逻辑，不能只有换颜色或加亮。 |
| 不同人物有不同插画 | 人物、场景和叙事事件必须是卡面艺术层变量，不能破坏途径根标识和层级外壳。 |
| 2:3，2048×3072 标准、4096×6144 收藏母版，PNG / sRGB | 文字、徽记和外框要在目标尺寸上落版；插画可经过分阶段放大，但不能把放大后的假细节称为原生细节。 |
| 六维语义契约 | 视觉不是“有气氛就算完成”；每个维度都需要证据、载体、回读和误读边界。 |

因此，本项目本质上不是普通的“角色立绘生成”，而是一个小型的**视觉语言系统 + 可控插画生产系统 + 卡片排版系统**。

## 2. 为什么一次性生成整张卡不是最佳方案

### 2.1 生成模型擅长概率性画面，不擅长项目级精确协议

扩散模型可以很好地处理构图、光线、材质、空间和事件气氛，但“某个路径的第 7 个专属数字必须有固定拓扑、中文名称必须逐字正确、边框必须落在安全区、同一人物跨三张卡要保持身份连续”是一组离散、可验证、跨图复用的约束。

公开研究已经反复说明，扩散模型生成准确文字仍然困难。TextDiffuser 把文字布局规划、字形渲染和图像生成拆开；GlyphControl 用字形条件输入控制文字内容、位置和尺寸；FonTS 仍把字体和风格的一致性、细粒度词级控制视为需要专门解决的问题。[1][2][3]

这对本项目的直接含义是：

- “心理医生”不能让模型直接写进最终图作为唯一正本；
- 途径根标识和融合后的艺术数字不能让模型凭提示词临摹；
- 生成图中出现的疑似文字、数字和徽记只能是草图或装饰参考；
- 最终文字和正式标识必须来自可编辑、可检查、可追溯的独立层。

这不是对模型能力的否定，而是职责分配问题。文字越精确、越复用、越不能出错，就越应该晚进入生成流程、以确定性方式落版。

### 2.2 途径和序列是结构约束，不是提示词形容词

ControlNet 的核心思路是冻结预训练模型，并额外训练能够读取边缘、深度、人体姿态、分割等空间条件的控制分支；T2I-Adapter 也明确把草图、颜色、关键点、语义分割和深度等外部控制作为文本之外的结构指导。[4][5]

由此可以推导出本项目的分工：

- 构图草图、主体位置和动作关系，用线稿 / 姿态 / 深度 / 分割等显式条件表达；
- 途径风格、材质和异常发生方式，用路径参考板、风格参考或图像提示表达；
- 层级的空间尺度和环境关系，用固定模板与构图约束表达；
- 具体故事事件，再由提示词和局部创作决定。

如果把所有要求都塞进一条提示词，模型需要同时猜测符号、布局、材质、人物身份、层级和文本，结果会出现“画面很好看但系统回读错误”的情况。

### 2.3 途径、层级、人物三者的变化速度不同

三类变量不应由同一机制承担：

| 变量 | 应保持什么 | 可以变化什么 | 最适合的载体 |
| --- | --- | --- | --- |
| 途径 | 根形、拓扑、异常方式、非色彩识别通道 | 局部节点、材质、事件化变体 | SVG 根标识、路径签名板、艺术层纹理 |
| 序列 | 在本途径内可学习、可递进 | 每条途径自己的数字变换、局部复杂度 | 参数化复合标记、序列字形词典 |
| 层级 | 宏观外壳和卡面结构可回读 | 空间尺度、边框状态、材质和标题区 | 矢量模板、布局模式、层级徽记 |
| 人物 | 身份核心特征和允许的年龄/服装范围 | 姿势、场景、叙事事件、光线 | 角色参考包、插画生成、局部修复 |

如果用一个 LoRA、一个风格参考图或一个“整卡提示词”同时学习四类变量，变化会互相污染：人物会带走不该带走的背景风格，序列会被角色服饰替代，层级会退化为亮度，途径会被颜色误读。

### 2.4 220 个卡位要求“可复用结构”，不是机械批量

本项目可以复用：

- 路径根标识；
- 10 个序列数字的变换规则；
- 四档层级外壳；
- 标题与文字安全区；
- 参考图和生成工作流；
- QA 检查表。

但不应复用：

- 同一路径十张牌的同一个主视觉事件；
- 同一人物在不同序列卡上的完全相同构图；
- 一张“通用 0–9 导轨”来代替每条途径的艺术数字；
- 一个颜色渐变来代替由低到高的能力和空间关系。

所以最佳对象不是“批量生成 220 个 prompt”，而是**批量生成 220 个受控任务包**，每个任务包指向同一套可复用结构，同时保留独立的语义、证据、事件和审核记录。

## 3. 公开技术证据：哪些能力值得采用，哪些不能承担正本职责

### 3.1 结构控制：ControlNet / T2I-Adapter 类方法

ControlNet 说明了空间条件可以作为独立控制信号接入扩散模型；T2I-Adapter 则把线稿、姿态、深度、分割和颜色等控制做成可组合的轻量适配器。[4][5]

对本项目最有价值的不是某个具体 checkpoint，而是这个架构事实：**结构必须以结构输入传给模型**。建议的使用顺序是：

1. 先在矢量或绘图工具中做卡面构图草图；
2. 按需要生成 lineart / canny、depth、openpose 或 segmentation 条件；
3. 让模型在固定构图中探索人物、环境、材质和光线；
4. 只在艺术层局部重绘，不重新生成已经确定的标识和文字层。

这可以显著降低“主体跑出标题区”“层级外壳被吃掉”“同一构图在不同候选中完全漂移”的风险。

### 3.2 参考图控制：IP-Adapter / InstantStyle / InstantID

IP-Adapter 通过与文本解耦的图像提示分支，为模型提供参考图，同时可与 ControlNet 组合；官方 Diffusers 文档也展示了图像提示、遮罩、深度/边缘/姿态控制以及多适配器组合的用法。[6][7]

InstantStyle 的研究动机是将风格和内容解耦，减少把参考图中无关的主体内容带进结果；InstantID 则针对单张脸部参考的身份保持，提供无需训练的身份条件路线。[8][9]

这几类技术适合承担：

- 路径签名板的材质、光线和纹理倾向；
- 人物参考包中的脸部、发型、服装轮廓和时代感；
- 同一人物在不同场景中的身份连续性；
- 同一层级的整体气质和视觉密度。

它们不适合承担：

- 最终复合标记的精确拓扑；
- 中文字词的逐字校对；
- 六维语义中的事实判断；
- 途径和序列 ID 的唯一性校验。

DreamBooth 和 LoRA 更适合在“重复人物很多、参考图已批准、身份漂移已经成为瓶颈”之后再评估。DreamBooth 通过少量主体图和唯一标识学习主体在新场景、姿势、视角和光线下的表现；LoRA 通过低秩可训练矩阵减少微调参数和显存开销。[10][11] 但对本项目第一阶段而言，过早为角色或途径训练适配器有两个风险：样本中的服装和背景被错误固化，以及风格/路径/人物变量不再容易拆开审查。

建议的身份控制梯度是：

1. 先用批准的角色参考包 + 图像提示；
2. 仍不稳定时，加姿态和脸部条件；
3. 只有在多个卡位重复使用同一人物、且参考集足够稳定时，才做 LoRA / DreamBooth 试验；
4. 每次适配器训练必须有独立的训练集、许可记录、版本和反向消融比较。

### 3.3 文字和徽记：研究性条件可以辅助，但最终仍应矢量落版

GlyphControl、TextDiffuser 和 TextDiffuser-2 说明了“在生成图中正确地安排和渲染文字”本身已经是一个专门研究方向；TextDiffuser-2 进一步把语言模型用于布局规划和逐行文本编码，但这仍然不是项目排版软件意义上的确定性文字排版。[1][2][12]

因此可以把生成文字分为三层：

- **正本层**：最终序列名称、途径名称、必要的准确信息；必须由文字工具或排版引擎生成。
- **结构参考层**：用于告诉模型“这里需要一个圆环、断裂数字、碑文状节奏或符号密度”；可以是灰盒字形或线稿，不承载最终内容。
- **艺术纹理层**：不可读的符号、裂纹、星图、纹理；必须避免让观察者误以为是正式文字或正式规则。

复合标记尤其适合用 SVG：SVG 是可缩放的矢量和混合矢量/栅格图形标准，能以与分辨率无关的方式表达路径、描边、填充、遮罩和负空间。[13] 这意味着同一个根标识可以在标准母版、收藏母版、客户端缩略图和测试版中保持几何一致，再分别做抗锯齿和材质化处理。

### 3.4 高清与放大：插画放大，文字和标识直接目标尺寸渲染

DemoFusion 采用渐进放大、残差和扩张采样来获得更大画面；SwinIR 和 Real-ESRGAN 分别代表研究性图像复原/超分和工程上常用的通用图像/视频复原路线；Diffusers 也提供文本引导的超分管线。[14][15][16][17]

这些技术支持的不是“任何 1024 图都能无损变成 4096 母版”，而是以下工作方式：

- 先在模型较稳定的工作尺寸完成主体、动作和空间；
- 对艺术层做分阶段放大或高分辨率重绘；
- 对文字、复合标记、外框和细线在 2048×3072 或 4096×6144 目标尺寸直接渲染；
- 放大后重新检查文字、细线、符号边界和小尺寸回读；
- 分别记录原始像素、最终像素和处理链，不能把“经过插值或超分”写成“原生生成”。

### 3.5 非破坏性图层：为什么“可编辑”是质量要求，不只是方便

Adobe 对非破坏性编辑的说明强调，调整图层、智能对象、智能滤镜、蒙版和独立修图层可以保留原始数据，并允许在不重做原图的情况下回退和修改。[18]

这和本项目的事实/视觉分离直接一致：

- 艺术生成失败，只重画艺术层；
- 文字错误，只改文字层；
- 路径标识规则迭代，只更新 SVG 根标识或变换；
- 层级模板迭代，只替换外壳和标题区；
- QA 发现误读，不需要冒险重新生成整张卡。

若使用支持节点图的 ComfyUI，官方仓库说明其工作流以节点图组织，并且生成 PNG 可以带回完整工作流和种子等信息；节点图还支持只重新执行发生变化的部分。[19] 这使它适合作为可复现的生成编排层，而不是把所有设计逻辑塞进模型提示词。

### 3.6 来源与 provenance：元数据有价值，但不能当作事实证明

C2PA 的指导材料把原始素材列为 ingredients，并支持记录来源关系、组件关系、AI/ML 动作和哈希；同时也提醒，manifest 并不轻量，元数据可能在传输、截图、导出或二次编辑过程中被剥离。[20]

所以本项目应采用双轨 provenance：

- 文件内：可选 C2PA、PNG 元数据、编辑软件信息；
- 文件外：项目自己的 `provenance.json`、工作流、提示词、模型版本、种子、参考图摘要、蒙版和审核记录。

文件外记录必须是主记录。任何元数据都不能证明画面事实正确、原著来源正确或第三方素材具有再分发权。

## 4. 方案比较：为什么推荐“系统化混合管线”

| 方案 | 优点 | 关键失败点 | 对本项目的判断 |
| --- | --- | --- | --- |
| 一次性生成整张卡 | 速度快，画面完整，适合找灵感 | 文字、数字、徽记漂移；边框和安全区不稳定；难以局部修复；同人物跨卡不稳定；不可可靠复现 | 只适合概念草图和氛围探索，不适合作为正式母版 |
| 一张参考图 + 一次生成 | 比纯 prompt 更有风格或人物连续性 | 参考图内容、风格、构图互相泄漏；仍无法保证精确排版和标识拓扑 | 可作插画候选，但仍需外部结构控制和后期合成 |
| 全部手工矢量/绘画 | 文字、标识、边框、尺寸和事实最可控 | 220 个卡位的场景细节和人物变化成本高；容易过度模板化 | 适合设计系统、标识、外框、文字和关键修正 |
| 纯微调模型 | 某个角色或路径可能很一致 | 样本偏差会固化服装/背景；训练和授权成本上升；变量不易拆解 | 作为瓶颈解决方案，不作为首轮默认方案 |
| **矢量系统 + 受控生成艺术 + 非破坏性合成** | 结构可验证、人物和场景可变化、局部可修复、可批量复现、高清交付清晰 | 需要建立模板、参考包、工作流和 QA；初期设计成本较高 | **最适合本项目，建议作为正式生产基线** |

这里的“最佳”是基于本项目约束的工程判断，而不是声称某个工具在所有艺术任务上都优于其他工具。公开资料支持的是模块化控制、参考图控制、非破坏性编辑和矢量排版的必要性；具体模型仍应通过本项目试验集验证。

## 5. 推荐的端到端生产管线

### 阶段 0：先锁定批次规则，不先锁死单个品牌工具

正式批次开始前，建立一个“批次运行配置”，至少固定：

- 主模型及版本；
- VAE、采样器、scheduler、工作尺寸和放大方式；
- 使用的 ControlNet / T2I-Adapter / IP-Adapter / 身份适配器版本；
- 风格参考和路径参考的角色；
- 随机种子策略；
- 允许使用的 inpaint 强度和重绘区域；
- 最终输出色彩空间、像素尺寸和命名规则。

模型和云服务会变化，工具当前是否支持某个功能也会变化。因此项目规范应该锁定“控制能力和交付证据”，而不是把所有卡永久绑定到一个可能变化的产品名。

### 阶段 1：从事实和六维语义编译卡面任务包

每张卡在生成前应有一个独立的、可追溯的任务包。建议至少包含：

```text
card_id
pathway_id
sequence_id
tier_id
character_id                  # 可为空；人物身份不等于 card_id
identity_text
sequence_display_name
pathway_display_name
semantic_contract              # 六维：事实、证据、视觉载体、回读、误读边界
main_visual_event
art_direction
composite_mark_ref
tier_shell_ref
character_reference_set
structure_sketch_ref
exact_text_list
allowed_artistic_inference
known_gaps
```

其中 `semantic_contract` 先决定要表达的事实，`main_visual_event` 再决定如何把六维线索组织到一个主视觉事件中。不可把“画得像某种神秘气氛”作为六维语义的替代品。

### 阶段 2：建立每条途径的视觉签名包

每条途径先建立一个可独立审查的签名包，而不是直接制作十张完整卡：

```text
pathway-signature/
  root-mark.svg
  root-mark-dark.svg
  root-mark-light.svg
  rank-glyphs/
    rank-0.svg ... rank-9.svg
  composite-mark-samples/
    rank-0.svg ... rank-9.svg
  compact-mark.svg
  tier-variants/
  material-swatch.png
  anomaly-behavior-sheet.png
  confusion-guards.md
  legend.json
```

签名包必须能够回答：

- 不看颜色时，如何认出这条途径？
- 不看标题时，如何认出这条途径？
- 同一途径内部，如何区分 0–9？
- 同一数字在另一条途径中为何可以看起来完全不同？
- 序列 0 如何是该途径的终点形态，而不是所有途径统一加一顶王冠？
- 标识融合到卡面边缘或标题区时，如何保持层级外壳仍可回读？

### 阶段 3：以“数据拆分、视觉融合”实现复合标记

建议保留如下数据模型：

```text
composite_mark = pathway_root ⊕ pathway_rank_transform(rank) ⊕ tier_modulation(tier)
```

这里的 `⊕` 不是把三个图层简单相加，而是允许：

- 序列数字沿途径根标识的主轴生长；
- 数字成为根标识的孔洞、节点、断裂、环路或负空间；
- 途径根标识在不同序列改变边缘、密度、开合或方向；
- 复合标记局部刺入外框或标题区，但不能破坏层级外壳的宏观轮廓；
- 序列 0 可以成为该途径根标识的终态变形，但必须保留途径血统。

必须保留三个可逆的数据字段：

```text
pathway_root
rank_transform
tier_modulation
```

视觉上融合不等于数据上扁平。这样才能在未来发现“某个 7 和 1 混淆”时只改对应 `rank_transform`，而不是重新绘制所有卡面。

#### 复合标记的三条识别通道

每条途径至少使用三类非色彩通道，建议从以下集合中选择：

1. **核心拓扑**：轴、环、结、裂隙、分叉、孔洞、镜像、包裹关系。
2. **几何轮廓**：尖角/钝角、开放/闭合、向心/离心、对称/偏斜、连续/断裂。
3. **材料或纹理**：金属、骨、玻璃、纸、烟、液体、纤维、星尘、湿润表面等。
4. **异常发生方式**：折叠、侵蚀、渗出、反射、错位、重影、逆光、局部无视透视。
5. **负空间逻辑**：标识内部的空洞、遮挡和不可见区域如何组织。

颜色可以强化这些通道，但不能单独承担途径识别。

#### 0–9 数字语法的设计原则

- 先确定“同一路径内的语法”，再决定每个数字的具体造型；
- 0–9 应共享笔势、节点逻辑或变形规则，但不能只是同一字体换十个字符；
- 不能把数字的识别完全交给卡面文字；
- 数字在缩略图和低对比度情况下仍应有大致可回读的外轮廓；
- 同一 rank 在不同途径可以采用不同几何，因为本项目要表达的是“路径化的序列身份”，不是通用数字牌；
- exact `sequence_display_name` 仍然独立落版，用于事实校验和无障碍回读。

### 阶段 4：建立四档层级外壳和空间语法

层级不是“颜色越来越亮”，而是影响画面中主体、环境、边界和规则的关系。以下是视觉提案层面的方向，不是原著事实：

| 层级 | 主要视觉差异 | 可使用的表达 | 应避免 |
| --- | --- | --- | --- |
| 低序列 | 近身、局部、人物与物件关系清晰 | 较窄外框、有限负空间、局部异常、相对具体的物件 | 仅做暗色；把低序列画成没有能力的普通人物 |
| 中序列 | 行为开始改变局部环境和他人关系 | 更复杂的空间层次、双主体关系、纹理与边界相互作用 | 只增加光效、翅膀或装饰数量 |
| 高序列 | 规则、空间和观察方式发生变化 | 更大的负空间、远近尺度反转、边缘受影响、环境成为能力载体 | 直接把所有高序列画成通用神祇模板 |
| 真神 | 途径终态的世界/法则感 | 终态复合标记、宏观构图、稳定的层级外壳变体、克制的不可读区域 | 只加王冠、金光、触手或更高饱和度 |

层级外壳建议共享一个跨途径的外部轮廓，内部纹理、材质和局部异常可以由途径改变。这样观察者先读出“这是哪一档能力层级”，再读出“它属于哪条途径”，不会因为 22 条路径各自画一套边框而失去系统感。

### 阶段 5：只让模型生成艺术层

每张卡的模型输入应拆成五组：

1. **事件说明**：这张卡的一个主视觉事件，以及人物正在做什么。
2. **语义约束**：六维中需要由画面承担的可视线索。
3. **路径参考**：材质、异常方式、几何倾向和氛围，不让参考图替代复合标记。
4. **层级参考**：主体与空间的尺度关系、观察角度和边界状态。
5. **结构条件**：草图、姿态、深度、边缘、分割或遮罩。

提示词中不应把大量准确文本、完整规则或复杂卡面布局作为生成任务。可以明确写：

- “顶部和底部留出清晰安全区”；
- “中央为单一叙事事件”；
- “不要可读文字、不要伪造徽章、不要数字”；
- “复合标记和标题由后期矢量层提供”；
- “不把其他途径的材质或符号带入”。

这里的“不要文字”不是为了限制艺术，而是为了避免模型生成一个看似正式、实际错误的伪信息层。

### 阶段 6：局部蒙版修复，而不是反复整卡重抽

Diffusers 的 inpainting 管线通过图像、蒙版和提示词重绘指定区域；官方文档也建议在需要修复的情况下使用合适的 inpainting checkpoint。[21]

推荐的修复顺序：

1. 先冻结复合标记、层级外壳和文字层；
2. 对手、脸、服装连接、物件关系或边缘异常建立局部蒙版；
3. 低幅度重绘，只改变需要修复的艺术区域；
4. 对修复前后做语义回读，防止修复掉能力线索或误加下一序列能力；
5. 保存原始候选和修复版本，不能只保留最终图。

### 阶段 7：非破坏性合成和精确落版

建议把正式母版拆为以下逻辑层：

```text
00_reference_and_guides
10_generated_art
20_art_inpaint_and_retouch
30_pathway_material_overlay
40_tier_shell
50_composite_mark_vector
60_exact_text
70_accessibility_and_metadata
80_qa_annotations
```

其中：

- `50_composite_mark_vector` 不被艺术层覆盖；
- `60_exact_text` 使用真实文字、真实序列名和项目规定的排版规则；
- `70_accessibility_and_metadata` 不替代卡面文字，只提供辅助回读、ID 和来源；
- `80_qa_annotations` 不进入交付图，但随制作记录保存。

如果所用工具只能输出一张扁平图，也可以把它作为艺术草图或候选图，但不应把它当作正式母版的唯一源文件。

### 阶段 8：分辨率、色彩和导出

建议采用如下交付链：

```text
model_working_art
  → art-only upscale / high-res pass
  → target-size vector render
  → target-size text render
  → composite at 2048×3072 or 4096×6144
  → sRGB PNG export
  → thumbnail / grayscale / 100% QA
```

不要先把“整张包含文字的低分辨率卡”放大再期待文字恢复。这样会把字符边缘、徽记节点和细框交给超分模型猜测，正好破坏本项目最核心的识别层。

## 6. 具体工具链建议

工具选择应按职责，而不是按品牌崇拜。下面是一套适合首轮验证的角色分工：

| 职责 | 推荐能力 | 适用理由 | 边界 |
| --- | --- | --- | --- |
| 事实/任务编译 | 现有 `card.json`、`canon.json`、`cardctl.py` 和设计文档 | 让事实、证据、缺口和任务包可追溯 | 不把生成结果自动当作事实 |
| 复合标记和外框 | 任意支持 SVG 的矢量工具 + JSON/SVG 资产 | 精确、可缩放、可批量变体、易做混淆测试 | 需要人工设计和规则审查 |
| 结构化生成 | ComfyUI / Diffusers 这类节点或管线系统 | 能组合 ControlNet、T2I-Adapter、IP-Adapter、inpainting，并保存流程 | 不代表生成结果天然正确 |
| 路径/风格控制 | IP-Adapter / InstantStyle 或同类图像参考控制 | 用参考图提供材质和视觉语言，减少纯文本漂移 | 参考图可能发生内容泄漏，要拆分角色 |
| 构图/姿态控制 | ControlNet / T2I-Adapter 或同类空间控制 | 把草图、深度、姿态和边缘变成显式输入 | 控制过强会压扁艺术探索，需要小范围对比 |
| 人物连续性 | 角色参考包；必要时 InstantID；瓶颈明确后再 LoRA/DreamBooth | 逐级增加成本，先验证是否真的需要训练 | 真实人物、数据集和模型许可需单独审查 |
| 局部修复 | Masked inpainting + 非破坏性修图 | 保留已通过的边框、标识和文字 | 不用整卡重绘覆盖已确认结构 |
| 合成和排版 | Photoshop、Affinity、Illustrator、Figma 或同等能力 | 图层、蒙版、SVG、精确文字和目标像素输出 | 工具的扁平导出不能替代可编辑母版 |
| 概念探索 | 具备参考图、编辑器或风格参考的云端工具 | 快速寻找构图、材质和氛围方向 | 当前产品能力和授权条款需在批次前重新确认；不作为正式母版唯一来源 |

ComfyUI 的价值在于把生成过程显式化和可复现化，Photoshop/矢量工具的价值在于确定性合成；两者不是互相替代关系。Midjourney 的 Style Reference、Editor 和 Edit Model 文档显示其适合快速探索风格、参考和局部编辑，但编辑器提交后存在扁平化限制，因此更适合作为探索和候选制作环节，而不是项目唯一的可编辑正本。[22]

对于模型授权，不应依赖“某个模型通常可以商用”的口耳相传。以 Stability 当前公布的条款为例，不同模型、组织规模和使用方式可能适用不同条件；正式发布前必须针对实际模型版本、素材来源和使用者身份核对许可。[23]

## 8. 首轮试验方案：先验证系统，不先生成 220 张

项目现有工作流已经建议用一条途径抽取 9、5、3、1、0 五个节点，再用一条视觉上明显不同的途径交叉检查。本文建议把这组抽样扩展成四轮实验。

### 轮次 A：单途径、五个序列的系统证明

选择第一条样板途径，制作：

- 路径根标识；
- 0–9 完整艺术数字接触表；
- 四档层级外壳；
- 序列 9、5、3、1、0 五张测试卡；
- 同一个人物或序列原型只在必要范围内重复。

测试重点：同一路径内部能否学习数字语法；层级是否在不看颜色时仍然明显；复合标记是否既统一又有递进。

### 轮次 B：同一序列、两条差异途径的混淆测试

选取一条形状、材质和异常方式明显不同的途径，在相同的 9、5、1、0 序列节点制作测试卡。

测试重点：

- 相同 rank 是否可以视觉上不同而不造成系统崩溃；
- 两条途径的复合标记是否一眼可分；
- 四档层级外壳是否仍然属于同一系列；
- 颜色去除后是否至少保留两种以上途径识别通道。

### 轮次 C：同一人物跨序列的连续性测试

选择资料、参考资产和许可条件已经清楚的人物，制作 3 张不同序列或不同层级的卡。

测试重点：

- 脸部、发型、身体比例和时代感是否保持；
- 服装、姿势和场景能否随序列变化；
- 是否不小心把高序列的能力提前带入低序列；
- 人物是否压过途径与序列核心标识。

### 轮次 D：尺寸、复现和生产记录测试

对通过的 1–2 张卡分别输出标准和收藏尺寸，重复执行工作流，并比较：

- 工作流是否能重新得到同类构图；
- 标识 SVG 是否几何一致；
- 文字是否逐字一致；
- 放大是否改变艺术语义或制造伪细节；
- 元数据和外部 `provenance.json` 是否齐全；
- 输出是否确为 2:3、PNG、sRGB 和目标像素。

## 9. 建议的验收指标

下面是首轮试验可采用的起始指标，属于建议门槛，提交正式规范前仍应由项目方确认：

### 9.1 识别测试

请未参与绘制的观察者只看缩略图和一张简短图例，分别回答：

1. 哪条途径？
2. 哪个序列？
3. 哪档层级？
4. 画面中的人物/事件是否符合这张卡的主语义？

不要只统计总体正确率，要记录混淆矩阵，尤其关注：

- 同一途径相邻数字的混淆；
- 不同途径同一数字的混淆；
- 低/中和高/真神的混淆；
- 颜色关闭后的识别下降幅度。

建议先设一个可操作的内部目标：途径和层级识别率至少达到 90%，序列识别率至少达到 85%，并以混淆矩阵而不是平均分决定是否返工。这个数字是实验起点，不是原著规则，也不是未经验证的最终 KPI。

### 9.2 文字与标识

- 正式文字零错字、零漏字、零伪字符；
- 复合标记由指定 SVG / 矢量资产渲染；
- 同一 `pathway_root` 的跨卡几何关系可追溯；
- 0–9 接触表中每个数字都有唯一文件和唯一变换说明；
- 颜色变为灰度后，途径仍保留至少两类非色彩识别通道；
- 复合标记不被人物、粒子或背景裁掉；
- 缩略图仍可看出层级外壳和主要标识轮廓。

### 9.3 语义和事实

- 六维逐项有证据、载体和回读；
- 未知、未核验和解释性概括没有被画成确定事实；
- 配方/晋升没有错放成下一序列能力；
- 没有把角色外来力量或后续能力提前表现；
- 只有一个主视觉事件，次级线索服务于主事件；
- 人物连续性不取代途径/序列身份。

### 9.4 生产和交付

- 标准图像为 2048×3072，收藏母版为 4096×6144（如该交付需要）；
- PNG / sRGB / 2:3 检查通过；
- 原始像素、最终像素、放大或重绘步骤有记录；
- prompt、seed、模型、适配器、参考图、蒙版、工作流和审核人可追溯；
- 生成候选、修复前版本和最终版没有被覆盖删除；
- 最终批准由人工/视觉审核给出，自动检查不能代替批准。

## 10. 主要风险和停止条件

| 风险 | 迹象 | 处理 | 应停止什么 |
| --- | --- | --- | --- |
| 路径被颜色替代 | 灰度后 22 条路径混在一起 | 增加拓扑、轮廓、材料或异常通道 | 停止扩大色板，先修标识系统 |
| 复合标记被画面吞没 | 缩略图看不到根形或数字 | 提高安全区和对比度；改用矢量叠加 | 停止整卡重抽 |
| 同一路径 0–9 不可学 | 接触表只能看出“同一种装饰” | 重写 rank grammar，减少随机纹理 | 停止生成正式卡 |
| 不同路径过于同质化 | 同样构图、材质和异常方式反复出现 | 重建路径签名和禁用混淆表 | 停止训练全局风格适配器 |
| 人物身份漂移 | 同一人物五官、年龄或服装时代不一致 | 增加角色参考包或身份控制；必要时试验 LoRA | 停止把角色结果当批准资产 |
| 高序列只是加光效 | 视觉层级只能靠亮度判断 | 改变空间、边界、规则和环境关系 | 停止加装饰性粒子 |
| AI 伪造文字 | 出现近似汉字、假数字或假徽记 | 生成阶段禁用可读文字，后期精确落版 | 停止整卡交付 |
| 超分制造假细节 | 细线、脸、符号边缘不稳定 | 艺术层与文字/矢量层分离，重审目标尺寸 | 停止把超分称作原生高清 |
| 工作流不可复现 | 只有最终 PNG，没有参数和参考摘要 | 保存节点图、sidecar 和版本锁 | 停止批量扩展 |
| 授权或来源不明 | 模型、参考图或人物素材无清晰条款 | 记录许可证、保留替代资产 | 停止发布，不以画面完成替代授权审查 |

## 11. 最终建议

### 建议正式采用的生产原则

1. **先做设计系统，再做卡图。** 先完成 22 条途径的根标识、0–9 艺术数字语法和四档层级模板的最小可用样本。
2. **视觉融合，数据拆分。** 途径标识和序列数字在卡面上融合成复合标记，但在源文件和 JSON 中保留 `pathway_root`、`rank_transform`、`tier_modulation` 三层字段。
3. **生成插画，不生成正本信息。** 模型专注场景、人物、材质、空间和异常事件；正式文字、标识、外框和精确数字由矢量/排版层完成。
4. **用显式结构控制替代 prompt 堆砌。** 通过草图、姿态、深度、边缘、分割和蒙版传达空间约束；通过参考图控制风格和身份。
5. **先参考图，后训练适配器。** 只有人物重复和身份漂移形成可量化瓶颈时，才进入 LoRA / DreamBooth 等更高成本路线。
6. **每次局部修复，不轻易整卡重抽。** 已通过的核心标识、层级和文字必须冻结。
7. **艺术层可以放大，信息层必须重渲染。** 2048×3072 与 4096×6144 都从目标尺寸重新落版文字和矢量符号。
8. **先做五节点样板，再做跨途径混淆测试。** 建议从第一条样板途径的 9、5、3、1、0 开始，然后加入一条视觉上明显不同的途径，最后验证同一人物跨卡连续性。
9. **把 provenance 和人工审核视为交付的一部分。** 没有真实文件、制作记录和审核证据的图，不计入正式完成。

### 下一步最小交付

如果进入执行阶段，最合适的下一步不是批量出图，而是交付一个“视觉语言证明包”：

- 一条样板途径的 root mark；
- 该途径完整 0–9 复合数字接触表；
- 四档层级外壳；
- 5 张 9/5/3/1/0 插画测试卡；
- 一条差异途径的同序列对照卡；
- 一次灰度、缩略图、文字、尺寸和复现 QA；
- 一份真实工作流和 provenance 记录。

只有这组证明包同时通过“途径、序列、层级三维识别”和“艺术质量、文字准确、可复现、可编辑”检查，才值得把规则扩展到其余 22 条途径和 220 个正式卡位。
