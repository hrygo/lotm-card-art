# LotmCardStudio 原生画册 MVP 实施计划

版本：0.2.0 · 修订日期：2026-09-13 · 状态：方案审查修订；M1 垂直切片已实施，导入/持久化/正式资源仍未完成。

设计依据：[已讨论设计](../specs/2026-09-13-lotm-card-studio-design.md)。
审查依据与变更原因见[审查记录](../specs/2026-09-13-lotm-card-studio-review.md)。
本版替代 Git 提交 `9bae233` 中的旧实施计划；不将旧计划中的示例代码视为已实现代码。

## 1. 目标与边界

交付本地优先的 macOS 原生卡牌画册：导入内容库、浏览动态数量的身份卡、
分别管理收藏和愿望清单，主动唤醒卡牌并收听人工确认的台词与故事。

保持用户已确认的产品选择：

- macOS / Apple silicon 优先；SwiftUI + AppKit；网页、工坊、游戏、同步后置。
- 一条途径下每个序列容纳 0…N 张卡；220 是旧美术脚手架容量，不是收藏分母。
- 同一角色可有多个独立身份卡；共享角色族，独立卡面、故事、收藏与播放。
- 首页书架与画廊；详情大卡面、常驻右侧面板、底部故事抽屉。
- 默认静默、点击唤醒；互动第一人称，故事第三人称，仍由卡牌音色讲述。
- 微光与灵性脉动用于日常；显影仅用于特殊事件，不作每次打开的强制动画。
- 仅连接本机 SpeechRail，不启动、停止、下载模型，不调用云端。
- 原仓库只读导入，个人数据与音频缓存不写回仓库。

文档审查阶段只修订方案，不生成正式卡图、不修改生产数据、不开发 App、不发布或 push；
该阶段现已结束。当前施工按本计划推进，M1 已落地一个隔离示意内容的原生垂直切片。
客户端范围通过 `apps/AGENTS.md` 下沉，保留美术规则对内容生产的约束，
避免旧“仅美术生产”约定与已确认的新目标冲突。

## 2. 技术边界与目录

采用 SwiftPM，目标为 macOS 14+、arm64；最低系统兼容性是待验证目标，不是已验证声明。
初期不引入第三方运行时依赖。工具链版本在实施启动时记录，不将本机版本写成未经验证的最低要求。

计划新增：

- `apps/LotmCardStudio/Package.swift`
- `Sources/LotmCardStudioCore/`：模型、导入、用户存储、SpeechRail、播放协调。
- `Sources/LotmCardStudioFeatures/`：SwiftUI 画册与交互。
- `Sources/LotmCardStudio/LotmCardStudioApp.swift`：唯一 @main 入口和依赖组装。
- `Tests/LotmCardStudioCoreTests/`、`Tests/LotmCardStudioFeaturesTests/`：与上述 target 配套的测试。
- `scripts/build-app.sh`、`Resources/Info.plist`：本地应用打包。
- `docs/qa/`：测试结果、现场试听与视觉验收记录。

Sources、Tests、scripts、Resources 均位于 App 目录内。
不同时采用 main.swift 与 @main，不引用尚未创建的 target 或未定义的测试辅助函数。
共享 fixture 辅助代码需明确归属测试支持 target，或分别放入使用它的测试 target。

存储分四层：

| 层 | 责任 | 禁止 |
|---|---|---|
| Git 内容源 | 事实、证据、身份、叙事、制作和批准记录 | 用户笔记、凭据、缓存 |
| 不可变内容快照 | 已验证清单、内容和允许的资产副本 | 就地覆盖活动版本 |
| SwiftData 用户库 | 活动快照引用、收藏意图、笔记、标签、历史 | 替代原著事实源 |
| 本机音频缓存 | 可重建音频、配方摘要与完整性记录 | 充当批准凭据 |

先以协议隔离内容导入、用户存储、语音生成和音频播放器；UI 不直接操作 URLSession 或数据库。
不提前拆独立服务、插件系统或游戏引擎。

## 3. 必须先冻结的数据契约

### 3.1 序列、身份与旧数据兼容

领域关系为 Pathway → Sequence → CardIdentity 0…N。

- `slot_id` 标识序列位置，兼容旧 `lotm.fool.s09`。
- `card_id` 标识可独立收藏的身份，稳定且全库唯一，不从显示名称生成。
- `identity_kind` 为 `character` 或 `archetype`。
- 角色卡必须有 `character_id` 和 `identity_slice_id`；序列原型可不绑定角色。
- 异画放在同一卡的 `variants[]`，`variant_id` 在卡内唯一，不复制顶层 card_id。
- 角色时间线使用有依据的排序字段；缺少依据时展示“顺序未确认”，不能把序列高低当作时间线。

保留原 `sequences/<seq>/card.json` 的 0.3.0 契约与现有文件；
新增身份记录位于 `sequences/<seq>/cards/<slug>/card.json`，采用 0.4.0。
Schema 按版本分支验证，不能仅放宽版本枚举后让旧字段规则误套新记录。
新身份记录继续承担六维语义契约；复用事实通过引用，不能凭复制宣布重新核验。

旧记录导入为 `SequenceDraft`，完整保留六维研究内容、来源、制作状态及原始记录。
它不是确认身份卡，但不能被压成没有内容的空格。
空位只提供“加入愿望清单”操作，不自动替用户收藏或加入愿望清单。
未来将旧序列原型变成身份卡时，使用显式映射，不能悄悄改变旧标识含义。

扩展 cardctl 前，逐项核查路径解析、卡牌解析、校验、上下文依赖、摘要、
brief、status、release 和 CLI 选择器；不能只增加一条 glob。
旧 220 卡位的 scaffold 校验保持原语义，新增身份数量单独报告。

### 3.2 叙事来源与人工批准

`narrative.json` 是身份卡的可选旁车；缺少时仍可浏览收藏，显示“暂无可播放文本”。
旁车绑定 card_id，每条台词、章节都有稳定 ID。

将来源与编辑审批拆成两个维度：

- `source_kind`：canon / interpretation / original。
- `review.status`：draft / approved / rejected。
- `review` 记录审核人、时间、批准依据和被审核内容摘要。
- 摘要覆盖文本、人称、内容类型、事实引用和来源引用；依赖事实变化也须重新判定有效性。

仅当人工批准记录存在且摘要匹配、依赖引用有效时允许生成语音。
“不是 draft”、结构校验成功、卡面已批准，都不能代替台词批准。
原创文本也必须人工确认；界面始终显示原创标签。
卡牌是否 confirmed 另行依据当前制作批准与依赖有效性判断，
不得单凭 `production.stage == approved` 认定当前版本已正式批准。
测试中的合成批准数据只能存在隔离 fixture，不能写进真实内容库冒充批准。

### 3.3 收藏意图与内容资格

用户记录以 `library_id + card_id` 为键；library_id 稳定登记，
不得使用本机目录路径，也不得按仓库显示名称猜测同库。
同一内容库的目录搬迁不应丢记录；不同库即使 card_id 相同也不能串数据。

持久化用户选择，展示时再结合当前内容资格计算：

| 用户原选择 / 更新事件 | 更新后的行为 |
|---|---|
| 正式收藏，卡牌仍 confirmed | 继续计入正式收藏 |
| 候选收藏，卡牌升级 confirmed | 保留候选选择，显示“可转正式”，不自动代选 |
| 正式收藏，批准失效或内容降级 | 保留记录，显示“待复核”，暂不计正式进度 |
| 卡牌从来源移除 | 保留笔记、标签和历史，显示“来源已移除” |
| 新增卡牌或空位 | 默认未收藏；空位允许手动加入愿望清单 |

正式进度分母为当前快照有效 confirmed 身份卡集合，分子为其中用户正式收藏的卡。
分母为零时显示“暂无已确认卡牌”，不显示 100%，也不回退到 220。
喜欢、笔记、标签、首次收藏时间、最近打开时间独立保存。
播放完成按稳定条目 ID 与内容版本记录；播放失败或打断不计为完整听过。

ID 迁移仅自动处理已声明、无冲突的一对一映射。
循环、重复目标、跨库映射为错误；拆分或合并保留旧记录并列出待处理关系，
不自动复制收藏、不按名字相似度合并。

## 4. 导入与快照更新

### 4.1 清单与校验

快照采用版本化 manifest，使用明确 snake_case JSON 键和数组记录，
不直接依赖枚举键 Dictionary 的隐式 Codable 编码形式。
至少含 library_id、schema_version、snapshot_id、途径/序列/草稿/身份清单、
叙事、角色音色绑定、资产清单、来源与批准依赖、导入诊断。

扫描前定义允许读取的文件类别；拒绝路径穿越、绝对资产路径、逃逸符号链接、
不支持版本、重复 ID、ID 与目录归属不符及悬空必要引用。
导入器独立执行契约校验，不假设用户先运行过 Python 工具。
未知高版本不得默默按旧版本解释。

内容摘要由排序后的相对路径与精确文件字节 SHA-256 清单生成，
覆盖目录结构声明、空位与旧草稿、卡牌、叙事、角色与音色配方、资产、
来源、审核及其依赖基线。导入时间、源目录绝对路径不进入摘要。
不能只哈希实际卡牌而漏掉空位或事实来源的变化。

### 4.2 失败语义与事务

- 身份、结构、来源或必需依赖不完整：生成诊断报告，不激活部分库。
- 可选图片缺失、音频不可生成：保留完整元数据，以占位图或禁用播放降级，
  但若批准依赖该资产，必须同步使相应正式资格失效。
- 不把坏卡“跳过”后当完整快照替换旧库。
- “部分导入”只作为待修复候选及报告保存，不能改变活动内容或收藏计数。

提交顺序：

1. 在临时目录读入、校验、复制允许资产并检查摘要，确认源文件未在复制过程中改变。
2. 将完成的快照安装为不可变目录；此时还不是活动库。
3. 串行化同库导入，在单次用户库事务中更新个人记录关联和 active_snapshot_id。
4. 事务成功后刷新 UI；失败继续引用旧快照。崩溃留下的未引用目录可延后回收。
5. 不另存第二份独立 active.json 作为权威指针；迁移失败保留原用户数据库。

导入期间用户仍可编辑笔记；提交时读取最新个人记录或检查版本冲突，
不得以扫描开始时的旧副本覆盖用户新编辑。
首次导入、重复导入、更新、搬迁、崩溃恢复和失败回滚都要有测试。

## 5. SpeechRail 与播放契约

### 5.1 服务连接

以实施时的 SpeechRail 本地 OpenAPI 契约为准。审查时接口为：

- GET /health：检查 tts_ready；tts_warm 不是可用性的必要条件。
- GET /readyz：可用于诊断，HTTP 200 可能仅代表 ASR 可用，不能独立开放 TTS。
- GET /v1/voices：读取可用音色与能力。
- POST /v1/audio/speech：生成当前人工确认文本。

默认 loopback 地址为 http://127.0.0.1:8201。
MVP 仅接受经过解析验证的数值回环地址（127.0.0.0/8 或 ::1），禁用 HTTP 重定向；
不因内容包提供了 URL 就向该地址发送文本或密钥。
可选 Bearer key 由用户输入并保存在 Keychain，不自动扫描 SpeechRail 的 .env。

校验 voice 可用性、输入长度、speed 与 instructions 能力。
审查时输入上限为 4096；克隆音色仅 speed=1 且不接受 instructions。
实际实施需用契约与边界测试复核计数方式，不能凭界面字符数猜测请求合法。
长章节按句边界拆为受限片段，不改写文本，不丢标点；一章内顺序播放，
不自动串播整个内容库。原始文字稿保持完整。

状态请求可先采用 5 秒超时，合成采用可取消的 180 秒初始配置；
这只是可调整工程初值，不是性能承诺。冷启动实测后修订，不能一律 20 秒中止长故事。
voice_override 不可用时明确提示，不静默换成无关音色。

### 5.2 音色与缓存

角色基础音色、身份语气调整和显式覆盖分开记录。
固定 voice_profile_id 不证明跨文本声纹稳定；同一角色的不同台词需要真人试听验收。
VoiceDesign 不稳定时登记限制，选择已验证配方，不声称客户端能保证模型声纹。

缓存键至少覆盖：缓存格式版本、library_id、card_id、条目 ID、精确文本摘要、
有效音色绑定与配方版本、模型及已知实际后端/profile、language、speed、
instructions、输出格式和分段版本。
若实际后端身份无法核实，不推定跨 profile 缓存相同；要求明确修订配方版本后重建。

音频与元数据采用临时对象目录写入，解码与摘要检查通过后一次提交缓存对象。
限制单段下载大小（初始 128 MiB，可配置），不把错误 JSON 当音频存储。
损坏缓存允许清理对应对象并重试，不能清理整个用户库。
单元测试使用合法小型音频 fixture，不用假 MP3 字节证明解码成功。
遵循原设计：服务不可用时本期禁用播放，浏览、收藏和文字稿保持可用；
离线缓存播放不额外扩入 MVP。

### 5.3 播放协调

单一协调器管理 idle、loading、playing、paused、failed 及当前条目和进度。
每次播放请求有 generation token；网络响应、播放器完成回调、计时回调均需核对 token。
取消不仅停止 HTTP，还停止播放器与剩余分段；旧回调不得覆盖新卡状态。

必须支持暂停、继续、停止、重播和新请求打断；校验播放器实际开始结果。
没有可批准文本时返回明确 no_playable_content，不假装已播放。
自然完成才记录完整听过；可另存部分进度，失败和打断不得误记 awakened/story_heard。
停止和视图生命周期结束时清理计时器与观察者。
错误采用稳定类型区分服务未就绪、音色不可用、未批准、合成、解码、超时和缓存损坏。

## 6. 分阶段实施与检查点

每个任务按“失败测试 → 最小实现 → 通过测试 → 检查差异”推进。
编译失败只可证明缺少代码，不能代替业务断言的失败测试。
依赖顺序：T1 → T2 → T3 → T4 → T5 → T6 → T7 → T8。
T5 的测试设计可提前进行，但激活真实导入前必须完成事务实现。

### T1：范围与契约冻结

- [ ] 同步根指令阶段范围，客户端规则按目录下沉，保留旧美术验收约束。
- [ ] 定义身份 0.4.0、叙事、角色/音色、库身份与迁移清单的版本化 Schema。
- [ ] 记录上述 ID、审核摘要、收藏状态和导入错误的 ADR。
- [ ] 建立共享正反例语料，供 Python 和 Swift 校验器使用，防止两套规则漂移。
- [ ] 覆盖 0/1/N 卡、同角色多卡、无角色原型、重复 ID、未知版本与过期批准。

检查点：各字段有唯一职责；没有“非 draft 即获批”，没有强制所有卡绑定角色。

### T2：最小工程与隔离样本

- [ ] 创建实际存在的 SwiftPM target、@main、核心模型和测试支持。
- [ ] 建立一个途径、1–3 张身份卡、一个旧草稿/空位的隔离 fixture。
- [ ] 至少包含两张同角色身份卡与候选卡；测试批准记录明确标为合成。
- [ ] App 从 bundle 演示资源读卡面占位与文字稿，不访问用户真实库。
- [ ] 创建大卡面、右侧控制面板与基础故事抽屉，无自动发声。
- [ ] 能运行 swift build 和 swift test；测试不能需要真实模型。

检查点：可打开最小原生窗口，切卡和读稿；不得把 fixture 描述为已完成正典卡。

### T3：先验收“卡牌会说话”

- [ ] 实现 SpeechRailClient、fake、音色解析、批准门槛与单焦点播放器。
- [ ] 覆盖只 ASR ready、未批准、不可用 override、请求打断和旧回调竞态。
- [ ] 提供用户手动配置 loopback/Keychain 的最小设置入口。
- [ ] 用一条真正获人工确认的短台词做真实 SpeechRail 试听。
- [ ] 对相同角色至少两段不同文本试听，记录音色连续性，而不只检查 HTTP 成功。

检查点 M1：打开样卡 → 点击唤醒 → 听到声音 → 读稿 → 切卡停止旧声音。
服务或人工内容缺失时记录“现场试听待验”，继续独立软件工作，不伪报通过。

### T4：兼容导入与内容校验

- [ ] 扩展 cardctl 的完整路径消费链，保留旧 scaffold/release 语义。
- [ ] 实现 Swift 原始 DTO → 校验 → 领域模型，不将缺失字段默默填成确认状态。
- [ ] 保留 SequenceDraft，导入所有合法状态、事实引用和图片占位状态。
- [ ] 实现依赖清单与快照摘要、安全路径检查和候选诊断报告。
- [ ] 验证旧 0.3、新 0.4、混合库、损坏 JSON、空位变更及源文件中途变化。

检查点：同一共享语料在 Python 与 Swift 中得到一致有效性结果。
本阶段只创建候选快照，活动库切换在 T5 完成后启用。

### T5：持久化、收藏与原子替换

- [ ] 创建 SwiftData 版本化用户 Schema 和临时测试数据库。
- [ ] 实现笔记、标签、喜欢、三类收藏意图及打开/播放历史。
- [ ] 实现唯一活动指针事务、导入串行化与崩溃恢复。
- [ ] 覆盖候选升级、正式降级、移除、恢复、一对一迁移与拆分冲突。
- [ ] 覆盖导入期间编辑笔记、重复导入、不同库 ID 相同及目录搬迁。
- [ ] 在 App 中启用真实目录选择、导入报告和快照切换。

检查点 M2：导入 → 收藏并写笔记 → 替换 → 重启，个人记录仍在，失败时旧库可用。

### T6：完整画册体验

- [ ] 书架与画廊、搜索筛选、动态计数、最近打开/收藏。
- [ ] 角色聚合及有依据的顺序展示；每张身份卡仍独立。
- [ ] 右侧身份、六维状态、音色与收藏面板；故事抽屉含章节、文字稿和来源标签。

- [ ] 卡面保持 2:3；网格使用缩略图，详情按需加载，避免同时解码全部高清母版。
- [ ] 验证窗口缩放、键盘导航、可访问名称、对比度与 Reduce Motion。
- [ ] 日常动效克制；特殊显影可跳过且不阻塞操作。

检查点：1–3 卡真实体验与大量合成卡浏览分别验收；合成规模测试不算生产内容完成度。

### T7：长故事、缓存与异常闭环

- [ ] 实现分段、章内队列、暂停继续、重播、进度与完整听过记录。
- [ ] 实现完整缓存键、原子写入、真实解码验证、损坏恢复。
- [ ] 测试文本/审核/音色版本变化失效，取消、超时、超长输入、服务断开。
- [ ] 验证错误不污染收藏、不误记历史、不阻塞文字稿。

检查点：同一故事连续播放、暂停恢复和切卡打断行为一致；重试不并行发声。

### T8：打包、回归与交付证据

- [ ] 打包脚本只接受 debug/release，通过 swift build --show-bin-path 定位产物。
- [ ] 使用明确 arm64 构建，复制可执行文件、Info.plist 及 SwiftPM 所需资源 bundle。

- [ ] 记录最低系统兼容性是否实测；未实测不得宣称 macOS 14 已验证。
- [ ] 更新 README 与 QA，核查变更未包含凭据、真实个人数据、模型或缓存。

检查点 M3：最终 .app 的验收通过，而非只通过 swift run。
Developer ID、公证、公开发布、GitHub push 和 universal binary 不包含在本次实施授权内。

## 7. 验证命令与验收证据

实施时在仓库根运行原有回归：

```bash
python3 tools/cardctl.py check --level scaffold
python3 -m unittest discover -s tests -v
```

在 apps/LotmCardStudio 下运行：

```bash
swift build
swift test
swift build -c release --arch arm64
bash scripts/build-app.sh release
```

最后运行：

```bash
git diff --check
git status --short
```

脚本与工程在对应任务创建后才能运行；上述不是本次文档审查的已执行结果。
新增身份卡达到相应制作阶段时，另运行该卡 design/release 检查，
结构测试不代替原著核验、图像回读或人工批准。

测试 fixture 不复制用户目录、.git、.build、实际 App 产物或缓存。
若既有测试通过复制整仓库隔离，应改成最小 fixture 或明确排除新构建目录，
不能让引入 App 后的测试无意复制大型构建产物。

QA 至少分别登记：

1. 自动化：命令、时间、结果、关键业务断言。
2. 集成：最终 app 路径、系统与架构、资源与持久化、失败恢复。
3. 试听：真实服务状态、请求配方、播放完成、声纹一致性与人工结论。
4. 内容：卡面/文本批准依据及摘要；原创、候选与确认内容分别标记。
5. 未验证项：最低系统、冷启动耗时、缺失批准等不得以计划代替实测。

## 8. 完成与剩余风险

MVP 完成须同时满足 M1/M2/M3：可导入、浏览、主动唤醒、听故事、收藏、
读稿与安全更新，并有真实 .app 和相应验证记录。
只完成 fixture、fake 语音或结构检查时只能报告对应阶段完成。

主要外部条件是人工确认的演示文本、可使用的卡面素材与可用本机 SpeechRail。
缺少它们不阻止可独立验证的软件开发，但不能越过现场视听验收。
原著、图像、字体和声音的公开发行权利需在另行发布前审查；
开源代码许可证不自动覆盖主题内容与第三方素材。
