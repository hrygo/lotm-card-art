# 五档品质、框徽接口与角色叙事优化

> 执行方式：使用 executing-plans 与 TDD，在当前工作区实施；不提交、不发布、不自动生图或生成音频。

## 范围与验收

1. 统一当前 SOP 与 Skill 入口，明确五档材质、框徽联合受光、逐枚圣徽接口、零几何漂移和姓名双轴居中。
2. 为任务增加五档品质和带摘要的文字侧车输入；编译器自动绑定当前 SOP、色表及声明的侧车，并拒绝缺失依赖的快照。保留旧任务格式，不把旧四档合成器声明为新五档实现。
3. 建立角色叙事结构化合同与检查入口，覆盖问候、口头语、分章故事、身份时间切片、来源、剧透边界、逐字批准和声音授权。与现有 App 的 greeting/catchphrase/story 和 canon/interpretation/original 概念保持一致，不修改 App。
4. 先写失败测试，再实现并回归；保留旧图、旧批准和旧摘要。历史回执失配如实报告，不重写摘要掩盖失配。

## 不在本轮完成声明内

五档新素材的实际生成、十枚徽章的全部接触域制作、通用分区调色渲染器、现有 App 的内容导入及真实音频制作仍是独立实施与视觉验收任务。本轮不以输入合同代替这些产物。

## 测试计划

- 五档覆盖 0–9，拒绝非法序列、品质错配和将 high 当作新五档品质。
- 新任务快照包含色表/SOP/侧车；删依赖、改侧车或改色表均被拒绝。
- 叙事包校验三类内容、唯一 ID、身份、来源证据、文案摘要和批准；草稿可保存但不能进入声音制作。
- 运行相关单测、scaffold 与全量 Python 回归，分别记录新行为与历史依赖失败。

## 本轮结果

上述 SOP/Skill、任务输入与依赖校验、叙事合同/检查入口已实施；新增 8 项合同用例和原 15 项任务用例通过。全库未全绿，历史回执因程序摘要变化失配，未回写绕过。精确验证结果与未完成渲染/资产/语义迁移见 `reports/sop-five-tier-narrative-optimization.md`。
