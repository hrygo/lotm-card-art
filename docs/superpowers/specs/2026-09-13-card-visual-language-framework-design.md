# 成神途径卡牌视觉语言框架设计

状态：`proposed` 设计规范草案

日期：2026-09-13

## 1. 目的

为 22 条成神途径建立一套可持续扩展的卡牌视觉规则。规则必须让观察者在不阅读长文的情况下，先辨认：

1. 这张卡属于哪条途径；
2. 这张卡处于哪一个序列层级，以及具体哪个序列；
3. 这张卡中的人物是谁。

三者的优先级为：**途径—序列复合识别 > 层级识别 > 人物叙事变化**。人物插画应有足够自由度，但不能破坏前两层的稳定识别。

本规范定义的是视觉系统和内容边界，不代表 22 条途径的正典资料、正式徽记、已批准艺术资产或 220 张卡牌已经完成。

## 2. 已确认的核心决策

### 2.1 两条正交轴

卡牌采用“途径轴 N × 序列轴 M”的结构。

- **途径轴 N**：22 条途径各自拥有独立的视觉签名。
- **序列轴 M**：采用四种宏观层级 UI，并在每条途径内部提供一套可学习的 0–9 阶位数字语法。
- **人物层**：在两条轴规定的骨架内变化，不构成第三套竞争性的 UI 皮肤。

序列层级使用项目当前配置：

| 层级 | 序列 | 视觉职责 |
|---|---:|---|
| 低序列 | 9–8 | 人的尺度、具体场所、清晰动作、相对封闭的外壳 |
| 中序列 | 7–5 | 人物与异常力量并置，空间和关系开始被改写 |
| 高序列 | 4–1 | 权柄、规则、仪式关系和开放空间占主导 |
| 真神 | 0 | 途径权柄形成统摄性领域或概念结构 |

“低序列 / 中序列 / 高序列 / 真神”是项目层级标签，不替代具体途径的序列名称。序列 0 是正式序列卡位，不是特殊事件。

### 2.2 途径标识与客户端

每条途径同时拥有：

- 卡面使用的完整版核心徽记；
- 客户端导航、筛选和缩略图使用的简化版徽记。

两者共享 `pathway_id` 和核心主形，但不是把复杂卡面边框直接缩小。途径标识是本系列原创设计，必须标注 `origin=original_design`，不得称为原著官方徽记。

### 2.3 层级 UI 的宏观差异

层级 UI 可以改变边框、标题区和整体构图比例，而不是只改变颜色或小图标。

- 低序列使用相对闭合、稳定、接近人的尺度的外壳。
- 中序列使用交错、分层、边界互动的外壳。
- 高序列使用开放轴线、仪式关系或权柄结构的外壳。
- 真神使用全幅关系、概念空间或被重新解释的边界。

四种外壳共享统一的识别外轮廓；途径复合印记可以局部穿透、嵌入或改写边缘，但不得抹掉层级的宏观结构。

层级章为小型辅助标识：外轮廓在四种层级间保持统一，内部纹理和材质可随途径变化。卡面使用图形化层级章，客户端和详情页显示准确的层级文字。

### 2.4 颜色与材质

- 途径决定主色相与辅色家族。
- 层级决定明度、对比度、表面质感和边框状态。
- 颜色不能成为识别某条途径的唯一依据。
- 每条途径至少有三个非颜色识别通道：核心徽记、几何/轮廓、材质/纹样或异常发生方式中的三个。

层级材质不是固定的黑金滤镜。低序列可以偏哑光和实体，中序列可以偏层叠和半透明，高序列可以偏结构性反射，真神可以偏全幅、异质或近乎无边界的色彩关系；这些只是层级语法，具体材质仍由途径签名约束。

## 3. 核心身份组件：途径—序列复合印记

### 3.1 基本公式

```text
composite_mark = pathway_root ⊕ rank_transform
```

视觉上，途径根形和阶位数字共同生成一枚印记，不再默认呈现为“途径徽记 + 序列数字”两个并排组件。

语义上仍保留两个可解码部分：

- `pathway_root`：告诉观察者属于哪条途径；
- `rank_transform`：告诉观察者属于该途径的哪个序列。

复合印记是主视觉识别核心；途径名称与序列名称是文字核对层；底层数据仍以 `pathway_id` 和 `sequence` 为事实字段。

### 3.2 每条途径独立的数字语法

每条途径必须拥有一套内部连贯、可学习的 0–9 阶位数字系统：

- 同一条途径的 9→0 遵循同一组变形规则；
- 不同途径的同一个序列可以采用完全不同的字形、方向、结构和负空间；
- 序列 0 也必须是该途径根形的终极变体，不使用全系列共用的通用零号徽记；
- 卡面不使用 0→9 的连续导轨、刻度条或进度条；每张卡只呈现当前序列的复合印记；
- 不能把随机装饰、不可复核的抽象符号直接称作序列数字；
- 每套字形都要有项目图例和稳定的 `sequence` 映射。

各途径共享的是递进语义，而不是字形：

| 序列阶段 | 共享的视觉递进语义 | 具体字形由谁决定 |
|---|---|---|
| 9–8 | 根形完整、封闭、局部化 | 当前途径 |
| 7–5 | 根形开口、分层、交错或开始作用于外部关系 | 当前途径 |
| 4–1 | 根形扩张、偏移、重组为权柄结构 | 当前途径 |
| 0 | 根形成为领域、关系或全幅统摄结构 | 当前途径 |

这些是艺术转译规则，不是未经研究的能力断言。具体卡牌仍必须按照六维语义契约核验能力、配方、晋升和限制。

### 3.3 文字策略

卡面不使用“序列 01”“序列 09”等机械前缀。身份文字采用：

- 主识别：途径—序列复合印记；
- 小型辅助文字：途径名称；
- 准确序列文字：序列名称，例如“心理医生”；
- 人物文字：人物名或身份名，按人物卡方案确定。

艺术数字不取代准确事实。序列名称、途径名称和人物名称仍从各自事实字段或已核验人物资料取值；复合印记是事实的视觉表达，不是新的正典事实源。

## 4. 三层视觉结构

### 4.1 层级外壳

负责：

- 四种层级的宏观轮廓；
- 边框开放程度与介入方式；
- 标题安全区和信息密度；
- 人物、环境、权柄之间的空间比例；
- 小型层级章的统一外轮廓。

层级外壳必须在缩略图上成立，但不强制所有卡牌采用同一构图模板。它可以在 `scene`、`icon`、`ritual`、`conceptual` 等构图任务之间切换，只要保留层级语法。

### 4.2 途径—序列复合印记

负责：

- 途径根形和阶位数字的融合；
- 22 条途径的独立识别；
- 同一途径内 0–9 的可学习递进；
- 卡面与客户端之间的同源标识。

复合印记可局部穿透层级边框，但不得遮挡序列名称、途径名称和必要的人物主体。

### 4.3 人物插画层

人物可以变化：

- 主体人物、服装和身份状态；
- 动作、视角、场景和叙事事件；
- 扮演原则、能力因果、魔药线索、晋升条件和限制的具体载体；
- 颜色比例和局部光线，只要不破坏途径与层级识别。

人物不得改变：

- `pathway_id` 的根形和核心识别通道；
- 层级外壳的宏观结构；
- 复合印记的可解码关系；
- 途径名称、序列名称和文字安全区的事实职责。

## 5. 22 条途径视觉签名模板

下面的模板是每条途径的统一设计记录格式。填写时必须区分“原著断言”“解释性概括”“原创设计”和“尚未核验”。

| 字段 | 内容要求 |
|---|---|
| `pathway_id` | 使用 `catalog/pathways.json` 的稳定 ID，不因中文名称修订而改变 |
| `display_name` | 工作名称与别名；附名称核验状态 |
| `core_mark` | 原创途径根形；说明轮廓、构造和不可改变部分 |
| `compact_mark` | 客户端和缩略图使用的同源简化版 |
| `geometry_grammar` | 线条、角度、曲面、轴线、边框节奏和负空间规则 |
| `material_grammar` | 一种主材质，最多两种辅助材质；说明纹样与表面状态 |
| `phenomenon_grammar` | 异常力量如何改变空间、对象、关系或时间；不得凭空写成能力事实 |
| `palette_grammar` | 主色相、辅色和灰度下的辨识特征 |
| `rank_transform_0_9` | 该途径完整的 0–9 阶位字形、变形操作和图例映射 |
| `tier_modulation` | 低 / 中 / 高 / 真神四层如何改变根形、材质、边界和空间 |
| `zero_form` | 序列 0 的途径化终极变体；不可使用全系列通用零号 |
| `character_bounds` | 人物插画可变区域与必须保留的身份锚点 |
| `client_usage` | 客户端图标、筛选、详情页和无障碍文本的使用规则 |
| `confusion_guard` | 最容易混淆的途径及至少三项差异化通道 |
| `evidence_boundary` | 正典事实、设计提案、解释性概括和缺口的边界 |
| `qa_examples` | 缩略图、灰度、相邻序列和相似途径对照记录 |

## 6. 卡牌数量与身份模型

### 6.1 220 卡位的含义

`22 pathways × 10 sequences = 220` 表示每条途径的十个序列覆盖卡位。它不是：

- 人物数量；
- 唯一身份数量上限；
- 同一角色可拥有的卡片数量上限；
- 已完成、已核验或已批准的卡牌数量。

### 6.2 同一角色多张卡

一张人物卡至少通过 `card_id` 独立识别，并绑定对应的 `pathway_id` 与 `sequence`。同一角色可以拥有多张不同序列的身份卡，例如奥黛丽可以有多个不同序列的独立卡片。

内容来源、人工批准、个人收藏和人物身份不能混成一个状态字段。更新来源时必须保留旧草稿和个人收藏记录；不同序列卡不能因为人物相同而合并成一张。

## 7. 识别与质量门槛

### 7.1 三秒识别目标

在不阅读长故事的情况下：

- 360px 缩略图应能看到复合印记、层级外壳和序列名称；
- 观察者应能先判断途径与四层级别；
- 具体序列通过该途径已学习的复合数字、序列名称和详情图例核对；
- 人物插画不应成为判断途径和层级的唯一依据。

### 7.2 灰度与相邻对照

- 灰度或低饱和状态下，途径仍至少保留三个非颜色识别通道中的两个；
- 同一途径相邻序列必须共享根形，同时发生有依据的形变或空间变化；
- 不同途径同一序列可以使用完全不同的数字艺术形态；
- 最容易混淆的途径必须在形状、材质、空间机制或异常发生方式中至少有三项清晰差异；
- 序列 0 不得仅靠更亮、更大、王冠、翅膀、触手或黑雾表示。

### 7.3 事实与视觉的双重核验

复合印记和层级外壳通过视觉规则审核，但不能代替：

- 中文序列名称与途径名称的来源核验；
- 六维语义的证据、载体、回读和误读边界；
- 具体人物状态与外来力量的区分；
- 实际图片的文字、像素、素材来源和人工批准检查。

项目图例必须能从复合印记回到精确的 `pathway_id` 和 `sequence`，但图例本身也不能新增未经证据支持的正典事实。

## 8. 不在本规范内的内容

- 22 条途径的具体核心徽记和完整 0–9 字形，目前尚未逐条设计；
- 220 张卡牌的完整人物、配方、晋升、限制和能力研究；
- 正式图像、原图、分层源文件和用户批准资产；
- macOS 客户端的具体 Swift UI 实现；
- 游戏规则、对战数值和百科式正典数据库；
- 官方徽记或官方字体的声称与再分发。

下一阶段应按此模板逐条填写途径签名，优先从现有生产顺序的 `fool` 开始；每完成一条，都要做相邻途径、相邻序列、灰度和缩略图回看，不自动把设计提案标记为批准。
