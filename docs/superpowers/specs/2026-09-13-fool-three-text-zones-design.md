# 愚者途径三文字区边框模板设计

日期：2026-09-13

状态：proposed；已获得用户对版式方向的确认，尚未实施、生成或正式批准。

## 背景与目标

当前愚者五档边框使用一个中央底部姓名牌，无法同时承载途径名、序列名和角色姓名。本设计把边框文字接口扩展为三个固定文字区，同时保留已经确认的愚者柱状边框语法、顶部圣徽留空、中央插画窗口、底部品质钻石和五档材质体系。

用户确认的关键澄清是：左右不是两块完整面板。左右仍然是连续的柱状结构，只在柱体靠近文字的位置设置局部内嵌铭带；只有中央角色姓名区域使用完整主面板。

本设计将“低角色姓名”解释为“下方角色姓名”。如果该词实际代表另一个字段，实施前必须改字段契约，不得静默替换含义。

## 版式结构

    左柱体                                  右柱体
    ┌────────┐                            ┌────────┐
    │        │                            │        │
    │ 途径名 │                            │ 序列名 │
    │ 局部铭带│                            │ 局部铭带│
    │        │                            │        │
    └───┐                                ┌───┘
        └──────── 中央角色姓名主面板 ────────┘
                             ◆

### 三个字段

| 字段 ID | 位置 | 载体 | 内容规则 |
| --- | --- | --- | --- |
| pathway_name | 左侧柱体内侧局部铭带 | 柱体内嵌文字窗口 | 显示途径名称，例如“愚者” |
| sequence_name | 右侧柱体内侧局部铭带 | 柱体内嵌文字窗口 | 显示序列名称，不显示“序列 09”这类编号标签 |
| character_name | 下方中央主面板 | 完整精美姓名面板 | 显示角色姓名；序列原型卡可为空，不绘制占位文字 |

三个区域只承载文字值，不额外绘制“途径名”“序列名”“角色姓名”等说明标签。文字必须由合成程序根据结构化字段排版，Agentic 生图不得生成中文或英文文字。

左右文字默认横排、沿同一基准线居中。禁止竖排、旋转排版、自动把长文字挤出柱体或通过移动柱体解决溢出。超过安全宽度必须报告溢出并返修面板或字段排版参数。

## 视觉与材质规则

### 柱状承载

- 左右柱体的外轮廓、柱轴、帷幕折线、柱体明暗和愚者烟紫凹槽保持连续。
- 左右铭带是柱体中的局部凹入/浮雕文字窗口；其横向外宽略大于相邻柱体主体宽度，推荐铭带宽度为柱体主体宽度的 1.12–1.18 倍，首选 1.15 倍。
- 铭带只在文字所在的局部高度范围内略微外扩，外扩边界与柱体保持连续承接；不得沿整根柱体扩宽，也不得扩展为左右两块完整矩形面板。
- 铭带边界只包围文字所需的最小安全区域；边界外继续显示柱体材质，不出现第二道大卡框。
- 左右铭带与柱体属于同一 material_group，共用五档主色、光向、反射和边缘处理。
- 左右铭带不新增宝石、挂饰、托座、横梁或品质构件。

### 中央主面板

- 中央角色姓名区域是唯一完整面板，继承愚者底部铭牌的精美倒角、内凹、边缘高光和柔和烟紫承接。
- 中央面板的宽度优先保障长角色姓名的可读性；不为了塞入固定字号而缩小到不可读。
- 中央面板下方保留底部品质钻石的独立空间，文字不得压入钻石或改变钻石中心。
- 中央面板、左右铭带与柱体保持连续光照，不以贴图式纯色矩形覆盖柱体。

### 五档适配

低序列、中序列、圣者、天使、真神五档均使用同一三文字区几何。五档差异继续来自边框纹理、柱体材质、铭带表面和品质钻石的受控材质，不通过增加面板数量或改变文字区数量表达层级。

圣徽必须进行五档调色：10 个已确认的愚者融合数字分别派生低序列、中序列、圣者、天使、真神五种材质版本，共 50 个调色圣徽变体。调色只改变透明像素的 RGB/材质表现，不改变 alpha、轮廓、镂空、数字骨架、面具、连接点或放置坐标。每档主色来自现有 quality-color-tokens；愚者烟紫可保留在暗部和凹槽，作为途径识别副色。高光、金属边缘和宝石折射必须保留，禁止平涂或用调色掩盖细节。

圣徽调色和底部钻石放大属于与三文字区共同交付的独立材质/几何接口；本版式设计将它们纳入同一 v2 生产门禁，但仍不把未完成人工视觉确认的结果伪装成正式批准。

## 几何契约

本版式必须创建新的版本化几何锁，不覆盖当前五档 v1 输出。

冻结内容：

- 卡面外轮廓、左右柱体轴线和双帷幕结构；
- 顶部圣徽安全区、圣徽中心和可见高度计算规则；
- 中央插画窗口；
- 底部品质钻石中心和其独立保护区；
- 三个文字区的固定安全矩形、基准线、内边距和文字方向；
- 中央主面板与左右铭带的层序、裁口和 mask；
- 五档的同构关系。

允许变化仅限：

- 从旧单一姓名牌派生中央角色姓名主面板；
- 在左右柱体内部增加局部铭带文字窗口；
- 与文字窗口相邻的柱体局部承接纹理，但不能改变柱体轮廓和轴线。

禁止事项：

- 把左右铭带做成独立完整大面板；
- 移动柱体、插画窗口、圣徽安全区、中央钻石或外轮廓；
- 用 warp、registration、重新裁剪或每档偏移隐藏位置漂移；
- 通过 Agentic 生图重新猜测文字、姓名或序列编号；
- 用旧四档映射替代五档；
- 覆盖或改写当前 fool-five-tier-kit-v1。

## 生产架构

实施时建立三层输入：

1. 几何层：新的三文字区 geometry lock、外轮廓与固定 mask。
2. 材质层：五档边框/柱体/铭带/中央面板/底部钻石材质，以及 50 个圣徽调色变体，使用现有五档色彩配置。
3. 文本层：pathway_name、sequence_name、character_name 的结构化字段和程序排版参数。

Agentic 生图只用于研究柱体铭带与中央面板的材质、倒角、浮雕和光照承接；正式边框像素由确定性合成程序输出。文字和最终位置由程序负责。任何带有生图文字的研究图只能作为视觉参考，不能直接进入正式文字层。

输出采用新版本目录，例如 fool-five-tier-kit-v2；每个版本必须包含：

- 五档透明边框；
- 10 个序列装配边框；
- 50 个按五档调色的圣徽透明层，以及 10 个序列实际使用的圣徽绑定；
- 三文字区保护 mask；
- 深底/白底诊断；
- 文字安全区和实际排版测量；
- 输入、输出、工具和配置哈希；
- 五档映射、版本号、视觉审核状态和正式发布状态。

当前 fool-five-tier-kit-v1 保留为上一版可回溯基线。新版本不能覆盖旧目录，旧四档仍保持 retired-historical。

## 门禁与验收

机器门禁必须验证：

- 五档映射仍为低 9/8、中 7/6/5、圣者 4/3、天使 2/1、真神 0；
- 外轮廓、柱轴、帷幕、插画窗口和钻石中心的几何差异为 0；
- 左右铭带宽度为相邻柱体主体宽度的受控略宽范围，且只在局部文字高度内外扩，没有形成完整侧面板；
- 中央主面板只存在一个，且与底部钻石保护区不重叠；
- 三个文字安全区的坐标和层序稳定；
- 空文字字段不产生占位字或随机残字；
- 50 个圣徽调色变体与对应原始圣徽的 alpha/轮廓/镂空差异为 0；
- 五档圣徽主色可读，愚者途径副色和金属/宝石高光仍可回读；
- 真实 PNG、RGBA、sRGB、透明区域和输出尺寸正确；
- 长途径名、长序列名、长角色名在实际排版中不溢出、不越过柱体或中央面板；
- 文字实际笔画 bbox 与目标中心分别计算，不能只依赖 align=center；
- output、catalog、geometry、recipe、renderer 哈希一致；
- visual_status 保持 pending，formal_release_approved 保持 false，直至人工审阅和用户批准。

人工视觉验收必须另外确认：

- 左右仍然读作柱体，而不是左右两块面板；
- 三个文字区的视觉层级清晰：中央姓名最重要，左右为身份索引；
- 铭带与柱体材质自然连续，没有贴片、断柱或第二道框；
- 左右铭带虽然略宽于柱体，但仍被读作柱体上的局部铭刻，不被读作两块侧面卡板；
- 五档材质变化没有破坏三文字区的结构辨识；
- 角色姓名较长时，中央面板仍具有足够呼吸空间。

## 非目标

本设计不包含：

- 22 条途径的批量模板生成；
- 220 张正式卡牌生产；
- 人物插画或角色故事；
- 音频、客户端接入或正式发布；
- 重新设计 0–9 圣徽轮廓；
- 将序列编号恢复成“序列 01–序列 09”文字；
- 把左右铭带扩展为完整侧面面板。

## 实施顺序

1. 创建并审核三文字区 geometry lock 与字段 schema。
2. 为中央面板、左柱铭带、右柱铭带建立结构 mask 和保护区。
3. 以无文字参考图进行五档边框、铭带、底部钻石和圣徽调色研究。
4. 更新确定性合成器，先生成无文字边框和 50 个调色圣徽，再由文本合成器注入三字段。
5. 生成新版本五档及 9–0 序列装配物料。
6. 执行结构、透明度、文字安全区、圣徽 alpha、哈希和零漂移门禁。
7. 视觉审阅通过后，再决定是否把新版本设为 active candidate；在此之前旧 v1 不删除、不覆盖。
