# LotmCardStudio 详情页固定舞台与交互 UX 设计

这份规范固化已验收的详情页视觉方向，重点解决固定尺寸卡牌舞台与可变信息内容之间的布局关系，并为后续卡牌动效预留稳定的渲染边界。

视觉原型已由用户验收通过：[详情页效果图](../../assets/lotm-card-studio-detail-ux-v001.png)。原型图是布局与交互参考，不是生产 UI 资源；生产实现必须由 SwiftUI 正常布局流生成。

## 1. 设计结论

详情页采用“固定卡牌动效围台 + 弹性信息轨”的双栏主舞台：

- 左侧卡牌围台是固定几何锚点，不随窗口或文本内容拉伸、压缩或换位。
- 卡牌本体保持 2:3，围台比卡牌本体更大，提供光晕、粒子、视差、翻牌等未来动效的安全空间。
- 右侧信息轨吸收剩余宽度与高度，内容变长时由信息轨或详情滚动容器承担滚动。
- 身份与故事在同一信息轨内切换，不再把故事追加为底部全宽面板。
- 字幕属于语音操作上下文，固定放在播放操作下方；故事全文属于阅读上下文，固定放在故事模式内。
- 鼠标光标只表达真实可点击区域；视觉反馈不依赖光标，所有交互必须有 hover、pressed、selected 或 focus 状态。
- 卡牌动效不能改变父布局尺寸、推动文字、覆盖按钮或侵入信息轨。

## 2. 当前问题与依据

现有详情页截图暴露出以下结构问题：

1. 右侧身份面板使用无限弹性宽度，形成大面积空白墙，卡牌舞台与信息内容失去比例关系。
2. 故事抽屉位于首屏主舞台之后，长文本和控制器被推到窗口下方，用户无法在卡牌仍可见时连续阅读。
3. 字幕新增为独立容器后，语音、身份、六维信息和故事之间出现重复边界，垂直节奏被拉长。
4. 卡牌本体没有独立的动效视口，未来任何放大、粒子或空间效果都可能改变布局或遮挡邻栏。
5. 自定义按钮样式缺少 hover、pressed 和 focus 反馈；侧栏、卡片和章节行的指针语义不清晰。

这些问题不是内容数量造成的，而是固定元素与可变元素没有明确的布局所有权。

## 3. 布局不变量

### 3.1 尺寸与所有权

| 区域 | 规则 |
| --- | --- |
| 侧栏 | 继续使用有界宽度，当前 ideal 约 258pt，允许在 220–310pt 内变化 |
| 详情内容容器 | 宽窗口最大约 1240pt，水平居中，左右留出 32–48pt 内边距 |
| 卡牌动效围台 | 固定约 420×630pt，保持 2:3 视口比例，不参与弹性分配 |
| 卡牌本体 | 固定 2:3，当前约 320×480pt，居中放置于围台安全区 |
| 围台安全区 | 至少 40pt；当前目标为横向约 50pt、纵向约 75pt，不承载文字、按钮或其他布局内容 |
| 信息轨 | 使用剩余宽度，建议最小约 460pt、最大约 760pt |
| 主舞台间距 | 卡牌围台与信息轨之间固定约 28–32pt |

布局表达为：

```text
详情可用宽度 W
┌──────────── 内容容器 max 1240 ────────────┐
│                                            │
│  ┌──── 固定动效围台 420 ────┐  ┌─ 弹性信息轨 ─┐ │
│  │      动效安全空间         │  │ 身份 / 故事 │ │
│  │        ┌────────┐        │  │ 操作 / 字幕 │ │
│  │        │ 320×480│        │  │ 六维 / 正文 │ │
│  │        │ 卡牌本体│        │  │             │ │
│  │        └────────┘        │  │             │ │
│  └──────────────────────────┘  └─────────────┘ │
│                                            │
└────────────────────────────────────────────┘
```

### 3.2 弹性策略

- 卡牌围台设置更高的 `layoutPriority`，禁止被信息轨压缩。
- 信息轨使用 `frame(maxWidth: .infinity, alignment: .topLeading)` 吸收剩余宽度，但由详情容器的最大宽度控制，不得无限铺满。
- 详情主舞台使用顶部对齐，不使用等高拉伸；信息轨变高不能拉长围台背景。
- 当可用宽度不足以容纳“固定围台 + 间距 + 信息轨最小宽度”时，切换为上下布局；围台保持原尺寸，信息轨改为全宽。
- 不使用绝对定位、负偏移、固定高度遮挡内容或依靠 z-index 解决重叠。
- 长故事只让信息轨内容增长并进入正常滚动，不生成第二个全宽故事容器。

### 3.3 信息轨模式

信息轨顶部提供两个明确模式：`身份` 与 `故事`。

身份模式顺序：

1. 身份标题与内容状态。
2. 语音配置与主要操作。
3. 实时字幕轨。
4. 六维语义使用两列网格，在窄信息轨中退化为单列。

故事模式顺序：

1. 故事标题与来源状态。
2. 章节选择。
3. 故事正文。
4. 播放、暂停、重播和停止控制。

切换模式只改变信息轨内容，不改变卡牌围台位置、尺寸或动画状态。

## 4. 卡牌动效视口

### 4.1 视口边界

`CardMotionViewport` 是未来动效的唯一承载边界：

- 静态卡牌本体位于围台中心，保持当前视觉基线。
- 光晕、轨道、粒子、历史投影和翻牌层都在围台坐标系中渲染。
- 动效可以使用安全区，但不能影响围台的布局测量值。
- 动效不能覆盖右侧信息轨，也不能改变信息轨的命中区域。
- 动效层与卡牌内容层分离，后续可以替换实现而不改详情页几何。
- 围台当前不自动变成按钮；没有明确的放大、翻面或沉浸模式操作时，使用普通箭头光标。

### 4.2 动效等级

- 常态：微弱呼吸光与灵性脉动，不改变卡牌位置。
- 播放中：字幕和声音状态变化可以驱动围台内的声波或光线，不推动周边布局。
- 高序列或真神卡：允许空间裂隙、历史折叠和权柄扩散，但必须裁剪在围台内。
- 特殊事件：未来可以进入独立沉浸模式；不把大范围事件动效塞进普通详情页。

所有非用户触发动画都必须尊重 `accessibilityReduceMotion`。

## 5. 语音与字幕 UX

字幕不覆盖卡牌，也不独占底部空间。它位于信息轨的语音操作区下方，作为唯一的“正在讲述”反馈。

### 5.1 状态

| 状态 | 显示 |
| --- | --- |
| 初始空闲 | “实时字幕”与“点击唤醒后，当前台词会显示在这里” |
| 准备声音 | 当前台词、加载指示和“正在准备声音” |
| 正在播放 | 当前台词、波形提示和“正在讲述” |
| 已暂停 | 保留当前台词，显示“已暂停” |
| 已讲完 | 保留最后一句，显示“已讲完” |
| 失败 | 保留文字稿，显示“声音不可用”和可读的失败原因 |

问候语和口头禅显示完整短句；故事台词显示有限行数的摘要，并提供进入故事模式的明确入口。

故事模式中的正文是完整文字稿；当前章节增加轻量“正在讲述 / 已暂停 / 已讲完”状态，不再重复渲染第二份大字幕。
故事模式保留紧凑的播放状态与章节上下文，但不重复渲染身份模式中的完整字幕轨。

## 6. 鼠标、键盘与反馈

### 6.1 光标语义

| 区域 | 光标 |
| --- | --- |
| 背景、卡牌围台、卡牌本体、普通文本和状态标签 | 普通箭头 |
| 画册卡片、侧栏项目、途径项目、章节行和明确 CTA | pointing hand |
| 可拖拽分隔线（未来功能） | resize cursor；当前不提供 |

光标不是交互反馈的唯一来源；不允许通过整块面板统一变手型来暗示可点击。

### 6.2 视觉反馈

- 主按钮 hover 时提升琥珀金表面亮度与边框对比度。
- 次按钮 hover 时提升灵性青绿色边框和文字对比度。
- pressed 状态采用轻微压暗或收缩，不使用明显跳动。
- 画册卡片 hover 时最多轻微放大约 1%，同时增强边框；选中状态持续可见。
- 侧栏项目和章节行 hover 时出现低对比度背景带；当前项目增加稳定的左侧色标。
- 键盘 focus 必须有清晰焦点环，不能只依赖颜色或阴影。
- 非交互卡面、信息面板和状态芯片不改变指针、不制造 hover 假象。

### 6.3 可访问性

- 所有按钮保留可读的 accessibility label、value 和 hint。
- 字幕区域作为可读内容暴露给辅助技术，不把动态文案写成无意义的装饰。
- 颜色不是状态的唯一编码；播放、暂停、失败和批准状态同时使用文字或图标。
- 动效在减少动态效果设置下退化为静态状态变化。

## 7. 组件与实现边界

实现建议保持以下边界：

- `CardMotionViewport`：固定围台、卡牌本体和未来动效层的容器。
- `DetailRail`：弹性信息轨，负责模式切换和内容滚动。
- `LiveCaptionRail`：统一字幕、播放状态和故事入口。
- `IdentityReadbackGrid`：六维语义的响应式网格。
- `StoryPanel`：故事模式的章节、正文和播放控制；不再作为详情页底部兄弟面板。
- `InteractiveSurfaceStyle`：统一 hover、pressed、selected、focus 反馈和光标语义。

播放领域状态继续由 `SpeechPlaybackCoordinator` 提供；字幕展示不得直接访问音频播放器或 SpeechRail 网络层。

内容模型不因 UI 重构改变：`PlaybackCaption` 继续保存台词 ID、类型和文本；内容批准、收藏和卡牌身份边界保持不变。

## 8. 验收标准

### 8.1 几何验收

- 在最小支持窗口中，围台不被压缩，信息轨不覆盖围台。
- 在宽窗口中，右侧信息轨不会无限拉伸，整体内容保持居中。
- 进入故事模式后，卡牌围台位置和尺寸不变化。
- 章节正文变长时不遮挡按钮、不推动围台、不产生重叠。
- 围台内部预留可见安全空间，静态卡牌不贴边。

### 8.2 交互验收

- 只有真实可点击元素使用 pointing hand。
- 画册卡片、侧栏、途径、章节和主次按钮均有 hover 与 pressed 反馈。
- 键盘导航可以识别当前 focus；停止或失败后仍可阅读文字稿。
- 字幕在问候语、口头禅、故事和 SpeechRail 失败场景中位置稳定。
- 减少动态效果后，页面仍能表达选中、播放和失败状态。

### 8.3 工程验收

- Swift 单元测试覆盖字幕状态、章节上下文和停止清理。
- `swift test`、debug/release 构建和安装包资源检查通过。
- 至少对最小窗口、常用窗口和宽窗口做一次截图或原生手动验收。
- 视觉原型不作为生产资源打包；生产 UI 的几何规则与本规范一致。

## 9. 方案取舍

### 保留底部全宽故事抽屉

实现改动较小，但故事被推离卡牌、窗口高度变化时体验不稳定，无法充分利用固定围台作为主舞台。否决。

### 故事进入独立全屏阅读模式

适合长文本，但会丢失卡牌身份和动效上下文，作为未来沉浸模式保留，不作为默认详情页。暂不采用。

### 固定围台 + 弹性信息轨 + 身份/故事切换

固定元素、可变内容和未来动效各自拥有清晰边界；用户始终看见卡牌，故事和字幕又能在同一上下文内完成。采用。

## 10. 本阶段不包含

- 不实现真实卡牌动效本身，只固化动效视口和安全区。
- 不新增卡牌游戏规则、数值或战斗界面。
- 不改变卡牌内容事实、审批流程、收藏数据或 SpeechRail API。
- 不把生成的效果图直接当作 SwiftUI 截图或生产资源。

## 11. 回退方式

若实现验证发现某一交互或系统 API 在 macOS 26 目标环境下不可用，保留固定围台与信息轨的几何契约，回退到等价的 SwiftUI 原生控件反馈；不得退回到底部叠放故事面板或用绝对定位掩盖布局问题。
